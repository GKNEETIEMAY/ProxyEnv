# RouteSpan v0.3.0dev — M2 Windows Target Detection 设计

评审稿。设计基线为 `aaa5b9d9283d048cf52ffc22938e3bb6e1e50273`。M2 的目标是通过已验证的 SSH
目标识别 Windows 运行环境和可用的命令解释方式。检测结果仅供诊断。Windows 与 `Unknown`
继续拒绝平台写入，现有 Linux 命令和脚本路径保持原样。

## 接口

| 建议入口或类型 | 契约 |
| --- | --- |
| `target_os::windows::probe(target)` | 独立的后端只读入口。接收已由现有 SSH 逻辑解析的目标和认证上下文，返回 `Confirmed(WindowsShell)`、`Unknown(ProbeReason)` 或现有 SSH 传输错误。探测从显式的目标检查路径触发。 |
| `WindowsShell::{Cmd, PowerShell}` | 表示本次 SSH exec 接受的命令语法。PowerShell 5.1 与 7 共用一项。包装器接受同一语法时，结果仍表示有效语法，不能推断 `DefaultShell` 注册表值或可用权限。 |
| `ProbeReason` | 使用有限的诊断原因，例如响应缺失、格式异常、输出过限、超时、目标变化。OpenSSH 无法明确区分的错误保留传输错误。结果不返回原始 stdout、stderr 或远端环境信息。 |
| 写入入口 | 现有 `require_linux()`、同进程平台检查和 Skills SCP 门禁继续独立工作。`Confirmed` 仅归类为 `TargetOs::Windows`，探测结果不可用作写入许可。没有有效 Linux 证据时维持拒绝。 |

默认 shell 由 Windows OpenSSH 服务端配置，常见默认项为 `cmd.exe`，维护者可以改成 PowerShell。
命令参数传递还受 `DefaultShellCommandOption` 等配置影响。检测应该以实际执行回执为准。
[Microsoft OpenSSH 服务端文档](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh-server-configuration)
[Win32-OpenSSH DefaultShell](https://github.com/PowerShell/Win32-OpenSSH/wiki/DefaultShell)

## 探测顺序与回执

1. 复用现有 SSH 目标解析、有效配置指纹和认证上下文。每个候选通过 SSH exec 发送固定命令模板，使用 `-T`、关闭应用持有的 stdin、清空配置转发，复用禁止 Agent/X11 转发与复用会话的约束。使用已受信任的主机密钥，禁止探测自动更新 known_hosts。授权确认与首次交互认证走既有连接流程。
2. 先走 PowerShell 候选。用 PowerShell 专属语法执行只读的 .NET 平台检查，要求进程平台为 `Win32NT` 才输出 `windows powershell` 回执。语法适配 Windows PowerShell 5.1 和 PowerShell 7，无文件、注册表、服务或网络配置访问。
3. 仅在第一个候选正常收尾、没有 stdout，且退出状态为 0 或 1 时，尝试 cmd 候选。stderr 只做有界捕获，错误文案和系统语言不参与判断。cmd 使用固定常量比较的 `if` 语法进入 Windows PowerShell 5.1 子进程，使用 `-NoProfile -NonInteractive -EncodedCommand` 运行同样的平台检查，成功返回 `windows cmd`。初版 cmd 使用固定系统安装路径 `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`，避免按远端 PATH、`%SystemRoot%` 或用户输入组装可执行路径。其他安装位置或策略禁用该程序时返回 `Unknown`，由实机矩阵记录覆盖差距。外层 SSH 默认 shell 仍可以加载自身配置。
4. 每个候选生成独立的 128 位随机值，编码为 32 个小写 ASCII 十六进制字符。只有这个受限字面量进入固定探测模板。Windows PowerShell 的编码命令用 UTF-16LE 后做 Base64。模板不把主机、用户名、文件路径输入或远端报错拼入命令，不含重定向、管道和备用命令链。两种默认 shell 与非 Windows shell 的实际解析先由测试验证。
5. 只有退出码 0、stderr 为空且 stdout 为唯一一条匹配的完整 ASCII 记录才确认。允许一个 `LF` 或 `CRLF` 行结束。拒绝前后缀、额外行、空行、BOM、NUL、其他控制字符、错误随机值及候选类型不符。正向回执之外的 stdout 直接返回 `Unknown`。SSH 退出 255、信任或认证失败、取消、断连、超时、输出超限时终止，不再尝试候选。返回前复核目标指纹，变化则丢弃结果。

```text
ROUTESPAN_TARGET/1 <32位小写十六进制随机值> windows <cmd|powershell>\n
```

建议每个候选的 stdout、stderr 分别限 4 KiB，两个候选共用 25 秒总预算，单次连接超时最多 8 秒。
并行读取两条输出流，任一超过上限或超时就终止并回收本地 SSH 子进程。退出后只保留分类与耗时。
25 秒预算内禁止候选自行重试。诊断结果绑定当次已验证的 SSH 目标与配置指纹，无跨重启缓存。
[OpenSSH 退出状态](https://man.openbsd.org/ssh#EXIT_STATUS)
[Windows PowerShell 命令行与编码](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_powershell_exe?view=powershell-5.1)

## 测试矩阵

| 范围 | 输入或环境 | 预期 |
| --- | --- | --- |
| Windows OpenSSH 实机 | 默认 `cmd.exe`，Windows 11 与 Windows Server；分别使用密钥、可用的本地 Agent 和服务器已启用的密码认证 | PowerShell 候选不匹配时进入 cmd 候选，确认 `Windows/Cmd`。主机密钥校验生效，无 SCP、转发或远端配置变化。 |
| Windows OpenSSH 实机 | `powershell.exe` 5.1 与 `pwsh.exe` 7 各作为默认 shell，使用实际的服务端命令选项及中英文环境 | 第一个候选确认 `Windows/PowerShell`，无需运行 cmd 候选。记录服务器与版本的真实兼容性。 |
| Windows 限制项 | 预置的 `ForceCommand`、受限会话、额外 stdout 或 stderr、非默认安装路径、禁止启动子进程的策略 | 按实际分类返回 `Unknown` 或 SSH 错误，无权限放宽、无写入。 |
| Linux 与其他 SSH 目标 | Linux `/bin/sh`、bash、装有 PowerShell 的 Linux、WSL 中运行的 Linux sshd；附加不受支持的 Unix 夹具 | Windows 候选均不产生正向结果。既有 Linux 适配器、26 项命令及载荷摘要、SSH 响应断言与未知平台拒绝测试继续通过。 |
| 协议和边界 | LF、CRLF、空输出、部分回执、重复行、BOM、NUL、随机值不符、候选不符、混合输出、正确回执伴随非零退出 | 仅两种合法换行和完整匹配回执通过；其他结果均不得产生 Windows 确认。 |
| SSH 生命周期 | 主机密钥不符、认证失败、配置指纹变化、断连、取消、慢输出、两条流分别越界 | 无进一步探测或平台写入，错误分类稳定，退出后子进程和管道已回收。 |
| 写入隔离 | Windows 已确认、`Unknown`、检测失败和过期结果 | 不进入 Linux/Windows 配置写入、SCP、Relay 启动或转发操作。 |

单元测试负责模板参数约束、字节解析及候选状态机。进程夹具覆盖两条输出流的限制、取消、超时和清理。
本地进程试验中，`cmd.exe /d /c` 执行 PowerShell 候选时退出 1、stdout 为空；执行 cmd 候选时退出 0，
回执正确且 stderr 为空。Windows PowerShell 5.1 和 PowerShell 7 各执行一次平台检查，均正常返回回执。
试验范围为本机 shell 语法，Windows OpenSSH 的命令转义、默认 shell 启动和 SSH 认证仍待实机测试。

## 风险与实施边界

- SSH 服务端能控制命令和回执。随机值用于区分当前请求与固定横幅或旧回执，无法提供远端 OS 证明。`ForceCommand`、自定义 shell 或转接至 WSL 时，结果仅反映本次 exec 的可见环境。
- Shell 启动脚本、`cmd` AutoRun 和安全策略由目标管理。额外输出或阻断会造成安全拒绝。探测只约束自身命令，无法改变远端登录钩子和 SSH 自身的审计日志。
- 候选的 0/1 退出状态、Windows OpenSSH 参数转义和 cmd 的固定安装路径需验证。若某部署走其他退出状态或安装路径，初版按 `Unknown` 处理。实机确认覆盖缺口后再评审兼容策略。
- 独立 SSH 调用可能遇到目标变化。配置复核用于丢弃过期诊断，主机信任沿用既有校验。任何未来 Windows 写操作均需单独设计其执行时的平台与目标复核。

本报告交付接口和验证设计。M2 实施、Windows 配置写入和网络桥接均等待各自的评审与授权。
