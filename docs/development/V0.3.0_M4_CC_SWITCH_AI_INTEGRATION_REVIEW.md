## A 本机服务识别

原始 `detect_cc`、`discover_cc`、`cc_route_ports` 和 `cc_route_healthy` 继续承担发现职责。用同一个状态观察器区分进程未发现、进程存在但服务未监听、端口归属待确认、服务已识别和服务不可用。已识别要求 `127.0.0.1`、唯一已知监听进程和有界 HTTP 200 健康 JSON。检查以固定回环地址请求 `/health`，关闭代理和重定向。保留旧 IPC `state` 和 `localPort`，添加 `service` 与 `revision`。Linux AI 初次预览在选定端口重新核对服务，避免以 TCP 可连接作为准入条件。

同端口所有者替换、监听端口变化或服务状态变化会推进观察版本。新结果发布后，旧探测无法覆盖它。E 验收修正了定端口检查与自动发现并行时的回执。若新发现的是另一个端口，原端口只报告待确认。当前观测无法发现同一进程、端口和健康状态下的 provider 切换或单工具路由开关变更，也未验证签名、账号登录、上游鉴权与模型可用性。[发现模块](../../src-tauri/src/features/remote_bridge/tooling/cc_service.rs)

## B Windows 会话所有权

复用现有 `LocalRuntime`、`Task`、Windows 计划与冻结配置校验、带签名的租约、安全回执及 `AuthenticatedRelay`。Windows 离线 AI 要求同一个任务的目标、SSH 配置指纹、主机身份和连接代次仍有效，且已有获准的传输资源和验证回执。另需明确确认 AI 能力，并匹配当前 CC Switch 服务端口和观察版本。准备收据按本次启用分配，停用后再次启用会产生新收据。旧收据和其他任务均无法改变当前资源。

普通代理与 AI 能力拥有各自的状态和资源。AI 可以单独关闭或因 CC Switch 更换而失效，托管终端继续使用 M3.4 的独立 Job。Windows 离线计划仍以已识别的活动代理准备共享传输，AI 目前没有独立建立 Windows 传输的入口。共享传输失效、撤销、过期或应用关闭时先撤销 AI Relay，再回收传输、终端和冻结文件。现有 Relay 的鉴权与请求处理继续使用原实现，关闭报告可区分 Relay worker 回收失败。真实 SSH 转发和用户流量的硬截止尚缺生产接线。[AI 会话](../../src-tauri/src/features/remote_bridge/target_os/windows/bridge/safety/runtime/local/ai.rs) · [现有 Relay](../../src-tauri/src/features/remote_bridge/relay/authenticated_relay.rs)

## 生产接线与 M5

生产实现目前缺少真实 Windows SSH 转发和 AI 专用运载接线、经验证的生产主机身份签发与信任保留、服务端许可及 IPv4/IPv6 实际监听验证、生产授权撤销和硬截止调度。开启生产能力前还需审查 relay 错误回收、受保护实际文件身份及权限、托管终端关闭后重启、终端启动失败与桥接资源隔离。受审主机清单保持为空。[M3.4 生产边界](V0.3.0_M3_4_WINDOWS_BRIDGE_INTEGRATION_REVIEW.md) · [M3.2-E 准入记录](V0.3.0_M3_2E_DESKTOP_INTEGRATION_REVIEW.md)

M5 由维护者验证 Windows OpenSSH、受管 Windows 主机、真实 cmd/PowerShell 与 PTY 进程树，验证 CC Switch 运行、未监听、账号/单工具路由切换及 provider 更换。还需复验 Codex 与 Claude Code 隔离应用、关闭和恢复、活动请求撤销、过期、断网、跨目标重连、应用退出和异常清理。Linux 验证原 SSH/SCP 流程、额外只读探测兼容、既有 AI 配置事务与 Clash Verge 和 CC Switch 联用。
