## 发现和隔离规则对照

| 边界 | 迁移前后等价行为 |
| --- | --- |
| Windows 发现 | `where.exe git` 取首行。Shell 优先读取 `PROXYENV_TEST_SHELL`，随后按原相对路径解析 Git Bash，最后按原条件回退 `/bin/sh`。用 `existsSync` 检查可用性，再按 `PROXYENV_TEST_PYTHON` 或 `where.exe python` 首行选择解释器。 |
| 非 Windows 发现 | Shell 默认 `/bin/sh`，Python 通过 `sh -c command -v python3` 发现。两个显式覆盖均保留 `||` 语义，空字符串继续回退。 |
| 执行环境 | 每次执行复制实时 `process.env`，先过滤 `/^(?:TEST_\|BASH_FUNC_\|MSYS)/i` 及原启动、Python、会话与扩展变量，再设置空的 `CODEX_HOME` 和 `CLAUDE_CONFIG_DIR` 以及夹具 `HOME`、`PATH`、`TMPDIR`，最后应用显式 overrides。代理变量继续按原规则继承。 |
| 模块装载 | 导入和创建工厂仅建立函数与闭包。合成装载记录进程和文件探测调用为零，实际导入前后目录与进程环境一致。 |

还原提取的发现代码、路径转换与环境构造，并移除两处导入接线后，测试入口和夹具均逐字节匹配 R4.5a。对 R4.4 最终基线和 R4.5a 比较 89 处 `test(...)` 注册的参数文本及源码摘要，顺序和内容一致，包含参数化循环、断言和平台跳过条件。`run` 与 `runSkill` 的函数体及 60000 ms 超时、Mock、配置恢复和 Shell 载荷字节一致。
