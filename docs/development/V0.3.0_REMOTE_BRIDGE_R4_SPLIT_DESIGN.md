# RouteSpan v0.3.0dev 后续模块拆分设计

R3 将根模块的测试移到同级测试文件。下列拆分是独立的后续工作，源码锚点对应 R3 的生产代码范围。[桥接根模块](../../src-tauri/src/features/remote_bridge/mod.rs)

## Rust 调用和共享状态

| 职责 | 当前调用 | 共享状态与拆分约束 |
| --- | --- | --- |
| 请求与对外模型 | Tauri 命令调用桥接入口，消费 `Request`、`Summary`、`Report`、SSH 状态和结果类型。 | 首选只移动低耦合 DTO，原模块通过相同可见性导出。核对 serde 字段名、默认值、错误码和 IPC 序列化。 [命令实现](../../src-tauri/src/commands/remote_bridge.rs) |
| 状态和投影 | `store`、`lock`、`try_lock` 创建 `StoreGuard`，释放时发布报告和托盘投影。 | `Store` 同时拥有进程、两种 Relay、连接代次、指纹、暂存配置和诊断。将锁与状态作为最后一项单独审查，维持释放顺序、try-lock 行为与投影时机。 |
| 监控与本机配置同步 | `start_monitor` 按周期观察桥接状态、轮询工具资料，进入 `sync_changed_profile`，由 `finish_profile_sync` 回写。 | 当前任务会受连接代次、本机配置缓存、`pending`、`profile_syncing`、进程及 AI Relay 状态约束。提取时保留轮询次序、忙状态和复核。 |
| 工具发现和自动配置 | `discover_tools_for_generation` 采集目标指纹和发现 ticket，复核后写入结果，`configure_discovered_tools` 进入受保护配置流程。 | 将参数收束为现有目标 ID、指纹、代次和 ticket。保留 SSH 调用前后验证和能力关闭优先级。 |
| 端口、CC 与直接观察 | `allocate_ports`、`resolve_port_pair`、`discover_cc` 和 `detect_cc` 汇总端口规则及本机候选。 | 纯端口计算可先独立移动。CC 服务探测、活动代理和外部 I/O 单列一笔。保留回环验证、端口区分、能力观测口径和现有网络预算。 |
| 配置事务 | `config_preview_locked`、`config_apply_locked`、`config_restore`、`verify_tool_for_generation` 委派工具或扩展适配器。 | 事务绑定预览、目标指纹、许可、会话和恢复凭据。预览与应用保留同一审批和失效边界，测试继续覆盖撤销、漂移、恢复及凭据脱敏。 |
| 会话和回连 | `connect`、交互连接完成、`disconnect` 和 `reconnect.rs` 管理 SSH/Relay，按代次调度 `start_post_connect`。 | 逐条核对旧进程关闭、目标复核、暂停通道、会话令牌及可选子任务的次序。保留连接路径和异步回写检查，避免提取接口后形成第二份会话所有权。 [回连源码](../../src-tauri/src/features/remote_bridge/reconnect.rs) |

后续提交顺序为对外 DTO 与纯端口计算各一笔，工具发现与直接观测各一笔，配置事务与监控各一笔，最后审查会话和状态边界。每笔用既有调用方、Rust/Node 测试和 Linux 26 项字节契约验证。读取根 Rust 源码的 `test-remote-bridge.mjs`、`test-updates.mjs` 和 `test-remote-network.mjs` 应按断言对应的函数更新文件入口。

## 独立 UI 拆分

| 候选范围 | 保留的接口与验收 |
| --- | --- |
| 目标列表和表单 | `storedTargetCopies`、`persistTargetCopies`、目标增删编辑、密钥文件选择以及输入验证。初步抽出纯验证与持久化操作。保留存储键、导入目标身份、错误定位、表单 ID、aria、现有父子 Props 与 Emits。 |
| SSH 认证 | `beginInteractiveAuth`、`pollInteractiveAuth`、提交、取消、重试及焦点。保持 `authBeginRevision` 与 `sessionId` 双复核、用户确认、提示清除和卸载失效。 |
| 连接意图 | `startConnection`、`connectPrepared`、配置确认与重连保持统一的 `connectionPhase` 和认证入口。保留用户确认次序、模态、无障碍焦点和成功事件。 |
| Skills 轮询 | `refreshSkills`、`scheduleSkillsPolling`、`stopSkillsPolling` 与 `toggleSkill` 依赖当前目标和状态。保留过期响应拒绝、单定时器、挂载和卸载清理。 |

优先验证无模板变化的提取。随后用首次连接、布局、就绪视图、能力、认证和国际化夹具对照 Props、Emits、公开的 `requestTrayCapability`、DOM/ARIA、键盘焦点及视觉结构。[页面源码](../../src/features/remote-bridge/components/RemoteBridgePage.vue) · [首次连接测试](../../scripts/test-remote-first-connect.mjs) · [布局夹具](../../scripts/test-remote-layout.mjs)

## 独立脚本拆分

`test-remote-bridge.mjs` 中的 `fixture`、`posix` 和环境清理是第一组候选。拟放入 `scripts/remote-bridge/`，由原测试文件导入。保持入口的测试注册时机和顺序，把当前解析的 Shell/Python 工具路径、临时根和脚本片段作为显式输入。保留每次夹具独立的工作目录与环境、现有超时、mock 输入、清理范围和平台跳过条件。通过逐项比较 Node 测试名及结果、扩展生成检查与 Linux 文件系统用例验收。[脚本入口](../../scripts/test-remote-bridge.mjs)

真实 Windows OpenSSH、Linux SSH/SCP 和 CC Switch 联合验收仍为 **PENDING**。
