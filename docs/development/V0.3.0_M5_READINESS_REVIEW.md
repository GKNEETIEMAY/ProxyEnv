## Ready-B Relay 关闭

复用 AuthenticatedRelay 会话、AiRoute 鉴权及原有 Codex HTTP 解析。会话撤销停止授权新连接，关闭已知双端 Socket，并取消等待首包与正在读取的 HTTP 请求。在连接释放前保留登记，跨一般代理转交的 AI 请求同时受 AI 会话撤销控制。普通代理的上游 Socket 附加到原请求登记，暂停后恢复时，旧请求无法重新获得上游。关闭报告记录监听是否结束、未回收连接数及线程失败。重试仍能检查原有所有者和清理状态。

常规关闭为两条 Relay 共用 5 秒期限。应用协调退出和最终兜底分别使用原有 3 秒和 200 毫秒期限。应用协调路径先等待已登记的桥接操作，再退役会话。超过期限仍由连接线程持有的项计入未完成。普通代理保留 Windows 已验证的阻塞式回环建连。撤销后，仍在建连的线程完成时无法登记套接字或发送数据。受控本机服务可以观察到客户端连接中断。真实上游模型任务的服务器执行状态需要上游独立证据。[Relay 生命周期](../../src-tauri/src/features/remote_bridge/relay/authenticated_relay.rs) · [Codex HTTP](../../src-tauri/src/features/remote_bridge/relay/codex_relay.rs)

首轮 `connect_timeout` 在 Windows 造成普通 HTTP CONNECT 双向交换失败，独立复跑 8 轮中 7 轮超时。恢复原回环建连后定向用例和完整 Relay 套件通过。保留初始失败和复跑日志。

## Ready-C 能力、终端与配置

Linux 合成回归覆盖网络-only、AI-only、两个能力启用及逐一关闭。Windows 现有受管计划仍需要活动代理来准备共享传输。独立 AI 生产模式需要为该能力签发单独的已验证远端端点、只启用经批准的监听和运载，并复用同一任务代次。该接线及安全设计留在维护者审批点。

托管终端只有在前一 Job 已清理时允许重开。每次启动具有独立回执关联，旧结果无法关闭或确认新终端。单独进程启动错误的收尾留在终端范围。目标、授权、冻结文件或传输失效继续影响整个会话。终端专用夹具保有原有整体清理路径。[托管终端](../../src-tauri/src/features/remote_bridge/target_os/windows/bridge/safety/runtime/local/managed.rs)

工具配置渲染显式接受本机 Relay 夹具端点类型。现有已检查的远端转发结果仍由 PreparedForward 表示；生成生产工具访问端点所需的真实传输验证接口尚缺。隔离配置继续复用 ToolAdapter、会话所有者和源摘要。临时文件仅在私有 NTFS 目录内独占创建，保留打开句柄、文件 ID 与内容证据。跨任务、目标冲突、外部替换、部分写入和重复恢复在本机验证。[临时配置](../../src-tauri/src/features/remote_bridge/target_os/windows/bridge/safety/runtime/local/ai/tool_config.rs)

CC Switch 的观察版本覆盖进程、端口和本地健康状态。v4.0.18 的 /health 表示本地服务响应。/status 使用运行期代理状态。缺少可依赖的跨版本契约来据此判断单工具路由或供应商配置变更，账号与模型能力继续按实机结果区分。[CC Switch v4.0.18 处理器](https://github.com/farion1231/cc-switch/blob/v4.0.18/src-tauri/src/proxy/handlers.rs#L58-L71)
