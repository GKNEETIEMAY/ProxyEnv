## 状态与所有权

| 状态 | 进入条件与行为 |
| --- | --- |
| 未登记 `Unregistered` | 离线批准登记路径的初态。持久层须明确确认该作用域从未登记，随后还需有效签名和提交。 |
| 等待验证 `AwaitingVerification` | 已登记会话的初态，也是查询和提交期间的中间态。没有可用授权。 |
| 有效 `Active` | 协议证据、目标快照、时间和历史一致性检查通过，且持久层确认提交。每次使用前须重新检查当前快照、截止和存储。 |
| 已撤销 `Revoked` | 读到已撤销的历史状态，或带有效证据的新撤销已提交。该审查作用域的后续会话拒绝继续使用。 |
| 已到期 `Expired` | 墙钟或单调时间任一达到硬截止。原会话停止，后续授权走新会话验证。 |
| 无法确认 `Unconfirmed` | 签名、来源响应、挑战、时钟、目标、可信历史前后值任一不一致。当前会话关闭。 |
| 存储异常 `StorageFault` | 预期已登记但记录缺失，读取损坏或失败，或提交失败及并发冲突。当前会话关闭。 |
| 已停止 `Stopped` | 显式停止。重复停止幂等，原会话不能靠刷新恢复。 |

`PolicyLifecycle` 保存单个会话的当前决定、完整租约作用域和最近一次时钟样本。`HistoryKey` 按签发公钥、审查 ID、修订、部署分隔。账号、SSH 地址和端口、主机密钥、配置指纹、代次、转发端口留在 `LeaseScope` 并逐次比较。会话间共享的只有经过验证的审查历史。登记标记由调用层提供，正式登记入口仍需独立审核授权及受管理的登记资料。

`Decision` 保存最高状态序号、撤销位和语义摘要。摘要覆盖序号、签发时间、到期时间及撤销位，状态的签发方和审查范围由索引绑定。同一决定的 JSON 空白变化无需推高序号，同序号改变撤销决定或有效期会被拒绝。提交使用比较并交换，同序号重读也核对原值。高序号的撤销先做验签、作用域、新鲜度和历史检查，再提交已撤销标记。相同审查修订和部署中的后续授权直接拒绝，重新入册需使用独立批准的作用域。任何提交错误都关闭本次会话。

## 新鲜度与到期

`StatusSource` 接受包含随机挑战、已签租约字节摘要、权威作用域和单调截止的请求。响应保留原已签状态，并增加由相同审批公钥验证的独立用途签名。证明使用 NUL 结尾的 `RouteSpan/windows-forward-status-proof/v1` 域，JSON 中的 `challenge`、`lease_sha256`、`status_sha256` 都为固定 32 字节。签名覆盖原始证明字节，两个摘要绑定已签租约和状态的原始字节。旧回复只能对应原请求。签名与解析继续走原有有界入口。新鲜度证明沿用已签状态的有效期，查询截止取现有 60 秒状态窗口、租约剩余时间和当前会话硬截止的最早值。未来权威来源须在独立认证通道内及时签发它已提交的最新状态，并在超时或异常时结束查询。

使用可注入墙钟与单调样本，在查询前、收到响应后和提交后复核当前范围和时间。授权硬截止取租约及状态最早期限，租约受审查有效期约束。会话首个有效样本给签名期限设置单调上界，墙钟停滞期间即使权威签发了较高序号，也不能推迟同一租约的硬截止。重新取得同一决定的新挑战回执会保持现有截止。任何时钟回拨、来源异常或上下文漂移均关闭当前会话。提交成功后，若授权已经到期，存储保留已验证的历史，当前会话仍不可用。

本轮只验证同步模型中的决策和夹具中的并发交错。未来生产所有者必须独立调度硬截止和主动撤销，确保权威查询或存储阻塞时也能立即停止接收新流量、关闭现有连接并回收资源。[Windows 网络桥接设计](V0.3.0_M3_WINDOWS_NETWORK_BRIDGE_DESIGN.md)

## 持久化边界

`PolicyHistory` 定义读取、比较、提交。确认从未登记和已登记记录遗失是不同结果。内存夹具把登记标记和状态组合起来，用互斥锁验证比较与更新的原子性，用合成错误覆盖遗失、损坏和不可用。并发用例在一个请求读取旧历史后让另一个会话提交撤销，然后再交付旧请求的有效签名响应，确定性地验证旧提交无法覆盖撤销。

生产存储需要当前用户 SID 限定的 DACL、当前用户 DPAPI、独立作用域、跨进程锁、同卷原子更新与刷盘恢复验证。写入或恢复的结果不明确时，该会话保持关闭。DACL 和 DPAPI 只能提供访问保护和内容完整性，整份历史回滚仍需从独立权威取得绑定新挑战的最新状态。权威端也需验证序号持久化、恢复后的单调性和签发一致性。普通内存夹具和模拟损坏只提供离线逻辑证据。
