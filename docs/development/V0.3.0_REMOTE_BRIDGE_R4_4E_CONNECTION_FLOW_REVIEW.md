## 依赖审计

初次 RustSec 直连失败。按本机网络配置完成复验后，原锁文件的 `cookie 0.18.2` 和 `url 2.5.8` 分别命中两条新公告。Cookie 公告的暴露条件涉及 Unix 上的私有 Cookie 与 fork。URL 公告的暴露条件涉及对不可信输入执行受影响的 origin 计算。审计以退出码 1 结束。[cookie 公告](https://rustsec.org/advisories/RUSTSEC-2026-0594.html) · [url 公告](https://rustsec.org/advisories/RUSTSEC-2026-0592.html)

获批后在 `402219db83da0c3c8681b18266782cee6424f301` 独立更新锁文件。`cookie` 升至 `0.18.3`，`url` 升至 `2.5.9`，后者要求 `form_urlencoded 1.2.3`。Cargo 仅重解析这三个包。锁文件 SHA-256 为 `4f7599a8752e90e3a83ab8fac0547d28d6843283594f1b418cf3ef483e6910d5`。完整 RustSec 复验加载 1567 条公告，完成 crates.io 查询，扫描 569 项依赖，退出码为 0，保留 16 条既有允许级警告。严格 Clippy、Rust lib 349 PASS 和前端高危审计通过。

## 连接流程提取
