## 目录与行为对照

```text
remote_bridge/                          R4.2
├── mod.rs                              发现状态、投影和配置事务均在根模块
├── port_allocation.rs
└── tests.rs

remote_bridge/                          R4.3
├── mod.rs                              共享状态、入口、调度及连接生命周期
├── port_allocation.rs
├── tool_state.rs                       发现状态失效和资格
├── projection.rs                       报告、摘要工具状态和会话命令投影
├── config_transaction.rs               预览、应用、恢复、验证
├── tests.rs
└── fixtures/projection_baseline.json    迁移前的合成 JSON 快照
```

| 依赖 | 调用与所有权 |
| --- | --- |
| 发现状态 | 对原 `Store` 借用。快照失效仅重置发现字段并推进 ticket。原回执校验继续绑定目标 ID、会话指纹、连接代次和 ticket。 |
| 投影与锁 | 报告只读已有观测，摘要工具投影仅修改传入摘要。锁释放时原样发布报告缓存及托盘状态。Serde 模型与 IPC 入口保留。 |
| 手动和自动配置 | 手动应用和恢复先验证用户确认，手动事务沿用原加锁位置。自动入口继续执行指纹、代次、ticket、用户 OFF 和并发事务检查。手动和自动配置复用一组预览和应用实现，按原顺序处理写入、回读与失败回滚。 |
| 预览与恢复 | 原 `Pending` 保留预览 ID、类型、目标、指纹、配置哈希和备份信息，生命周期继续负责清理。恢复只使用预览绑定的目标。 |
| 诊断验证 | 在原锁窗口采集会话信息，SSH 请求在两个锁窗口之间，回写时按原顺序拒绝旧代次、旧 ticket 或目标变化。 |

三阶段共迁移 13 个函数。按 Git 换行格式比对，函数体逐字节一致。可见性、格式化与所在模块调整见各阶段 Review。根模块除迁出定义和新增模块与导入声明外保持一致。三个 Node 用例的源码读取位置跟随事务模块调整，断言表达式保留。C 阶段首轮遗漏了共享适配器用例的读取位置，修正后完整复跑通过，失败证据和修正记录保留在阶段 Review。
