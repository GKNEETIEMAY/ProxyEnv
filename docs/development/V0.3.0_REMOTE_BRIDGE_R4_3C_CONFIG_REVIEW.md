## 迁移与事务依赖

| 迁移函数 | 状态及锁边界 | 保留的行为 |
| --- | --- | --- |
| `config_preview_locked` | 借用调用方已经锁住的 `Store`，使用原有 `Pending` 槽。 | 本地配置及路由校验、CLI/插件资格、目标指纹和端口校验、原 SSH 预览、权限加固提示和预览数据。 |
| `config_apply_locked` | 借用同一 `Store`，原顺序消费并校验预览，沿用当前 AI relay 令牌及预览绑定的目标 ID。 | 原指纹校验、写入后回读、配置和模型哈希复核、备份及失败回滚。成功后更新本地缓存及移除相应的用户 OFF 标记。 |
| `config_restore_preview` | 在原位置取得显式目标指纹，再加锁并写入原 `Pending` 槽。 | 恢复预览、原配置/备份哈希和权限加固参数。 |
| `config_restore` | 原样先检查显式确认，再加锁、消费恢复预览并验证预览目标指纹。 | 对预览保存的同一目标执行恢复，只有会话目标匹配时才更新本机投影、OFF 状态和配置缓存。 |
| `verify_tool_for_generation` | 原样在首个锁作用域内采集目标、指纹、端口、Relay 令牌、连接代次和诊断 ticket。锁释放后执行远程请求，回写前重新加锁。 | 旧代次首先被拒绝。结果回写前仍复核连接、目标、指纹、端口、令牌、ticket 和配置状态。诊断事件、错误分类和耗时保持原状。 |

手动 `config_preview`、`config_apply` 与 `verify_tool` 保留在根模块，恢复接口经根模块重导出。Tauri 命令及其签名保持原样。手动预览和应用入口以及 `configure_discovered_tools` 分别调用同一组 `config_preview_locked` 与 `config_apply_locked`。自动路径在事务前仍复核目标、指纹、连接代次、发现 ticket、用户关闭标记及手动事务占用。手动路径依赖既有的预览目标 ID 和指纹绑定、生命周期中的预览清理与确认，预览数据结构未增加字段。[事务实现](../../src-tauri/src/features/remote_bridge/config_transaction.rs) · [根模块](../../src-tauri/src/features/remote_bridge/mod.rs) · [Tauri 命令](../../src-tauri/src/commands/remote_bridge.rs)

`Pending`、`LocalToolProfile`、缓存逻辑与共享请求构造保留在原作用域。监控、本地配置变更识别、发现、扩展观察、`extension_pending`、`profile_syncing` 及连接生命周期仍由原调用层拥有。原来读取或写入磁盘/远端以及报告与事件发布的时机均由原函数体保留。
