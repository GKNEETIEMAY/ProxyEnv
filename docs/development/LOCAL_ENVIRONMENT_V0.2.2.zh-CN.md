> **状态：已授权实施 / v0.2.2dev**  
> **交付对象：本地 Codex（Windows / Tauri 2 + Vue 3 + TypeScript + Rust）**  
> **文档版本：v1.1 · 2026-10-21**  
> **基线：公开稳定版 v0.2.1；GitHub `main` HEAD `29c128570436a0ccc0c180d5e5561bac8d1179b6`（核对时）**  
> **仓库：** `GKNEETIEMAY/ProxyEnv`  
> **工作版本：** v0.2.2（开发中；未打 Tag、未发布）  
> **目标：** 本机环境的视觉与交互向远程桥接工作台对齐，在不更改现有网络/SSH 契约的前提下增强可理解性、可观测性和可靠性。

## 0. 给 Codex 的执行摘要

本次是**本机环境体验重构 + 现有连通性检测能力接入**，不是代理内核、网络协议或远程桥接重写。

1. 首先核对当前本地仓库和本文基线的差异。**以实际仓库源码和已通过的测试为行为真值**；存在差异时先汇报，不要为匹配文档而覆盖新代码。
2. 先完成 **M0（审计、交互设计、状态矩阵、预览）**，再实施 **M1～M5**。每个 Milestone 独立测试、独立提交、保留回退能力。
3. **仅允许本机环境内部添加“概述 / 高级”切换**；全局导航依然只有“本机环境 / 远程桥接”，应用助手仍是本机的上下文页面，不新建顶级路由。
4. 视觉风格复用远程桥接的现有组件、状态表达和主题 Token。**不重绘 Logo，不修改用户已定稿的浅色按钮白字、白色勾选和开关外观**。
5. 连通性检测复用现有 Rust 命令；**用户主动触发外网检查**，不引入周期性互联网探测。选择变更/回包竞态必须由前后端双重保护。
6. 不新增未经授权的后台代理切换、系统代理写入、TUN 管理、SSH 改动、普通网络鉴权、root 连接、MCP 或新 AI 客户端。
7. 不修改现有兼容标识，不移动历史 Tag，不替换 v0.2.1 发行资产。**未经维护者单独授权，不创建 v0.2.2 Tag、不执行公开 Publish。**

## 1. 产品定位与验收目标

### v1.1 审阅修订（2026-10-21）

- **授权与分支**：维护者已授权修订并实施，分支 `v0.2.2dev`，不再等待 M0 二次批准。开发保持版本号 0.2.1；正式发版另行授权。
- **变量操作契约**：同步写入勾选且协议支持的变量，清除其他受管代理变量；关闭清除全部受管代理变量；恢复使用快照而非勾选范围；NO_PROXY 只读。概述的同步操作旁显示变量名与清除影响，高级标题使用“同步后启用的变量”。手动确认必须说明同时改变当前代理和环境变量。
- **设置持久化**：勾选后立即同步时先等待最新设置保存；保存失败不执行变量写入，不能使用旧设置。
- **缓存提交**：检测完成后，必须在活动代理 revision 校验通过的同一临界区内提交缓存；缓存绑定 revision 和请求代次，旧请求不得覆盖后启动的请求。同一候选 A→B→A 不能恢复旧代次结果。诊断报告/应用助手读取也遵循相同 revision。
- **结果解释**：保持后端 2/3 成功即 reachable 的兼容聚合，界面始终显示实际通过数。监听失败后的协议/外网步骤显示“未执行”；协议无法确认显示“未确认”。远端拒绝与本机监听失败分开。请求失败属于操作状态，不伪造检测结果。
- **缓存时效**：展示检测时间，5 分钟后降为“结果已过期”；切换候选立即清除旧结果。前端保守地从 testedAt 起算 TTL，过期不自动检测；请求 ID 同时保护缓存读取与主动检测。
- **环境刷新竞态**：活动代理 revision 不是环境变量版本；同步/关闭/恢复前使已有刷新失效，操作后接收后端返回值，并排队一次可靠刷新。旧的同 revision 响应和错误不得回写。
- **紧凑布局**：概述突出当前代理、环境状态、连通性摘要；系统代理/TUN 紧凑只读展示。高级按端点展示候选，保留同进程的多个端口；无候选时仍可直接进入手动配置。详细错误、变量值和检测结果置于高级。
- **验证新增**：A/B 乱序完成、A→B→A、同候选重复检测、缓存过期/查询晚到、慢刷新期间同步/关闭/恢复、勾选后立即同步、设置保存失败、2/3 目标通过、同进程多端口和选择失效。
- **发布阶段**：M5 开发预检只验证源码与现有构建契约；实机升级、签名发行资产和公开 Release 验收记录为发布阶段待办，不把浏览器模拟或 unsigned build 当作完成。

### 1.1 当前问题

在 v0.2.1 中，本机与远程的外部工作区容器已经统一，但本机的内部布局仍以连续区块呈现：代理客户端 → Windows 系统代理/TUN 观测 → 环境变量操作 → 应用助手入口 → 变量明细。信息较密集，主要状态和动作不够集中。相较之下，远程桥接已经有清晰的工作区标题、分段视图、独立状态卡、能力区域和操作区。

本机后端已经实现活动代理选择、代理检测、环境变量备份恢复以及 **`test_current_proxy_connectivity`** / **`get_last_proxy_connectivity_result`** 两个检测命令；但当前本机主页尚无完整的结果卡片，前端共享 API 也没有相应调用封装。这部分属于**已有能力的 UI 接线与状态可靠性工程**，不是新建代理测试引擎。

### 1.2 成功标准

- **一眼识别**：进入本机环境即可看出当前选中什么代理、是否监听、系统代理/TUN 是什么状态、环境变量是否与当前代理匹配。
- **两步直达**：用户能快速切换已检测代理、手动配置端点、同步环境变量、打开应用助手和执行网络检测。
- **理解一致**：界面明确区分“代理已选择”“端口监听”“环境变量已应用”“外网请求通过”；互不冒充。
- **视觉一致**：本机与远程使用相同的标题层级、卡片密度、间距、StatusIndicator、图标大小、按钮体系和滚动策略。
- **行为不退化**：代理选择仍只有一个后端权威来源；远程桥接读取同一选择状态；已运行进程和第三方客户端不被静默修改。
- **发版可证**：四语言、四配色×两明暗、Win10/11、窗口缩放、代理状态矩阵均有回归依据。

### 1.3 本次不做（明确排除）

| 不做 | 原因 |
|---|---|
| 代理核心、系统代理、TUN 开关/规则编辑 | 与 RouteSpan 的辅助工具定位相冲突，影响系统级网络状态 |
| 发现新客户端后自动切换活动代理 | 可能让远端桥接或新进程意外使用其他上游 |
| 自动重启 Clash/v2rayN/其他第三方客户端 | 不拥有第三方程序进程生命周期与配置 |
| 定时请求 Google/GitHub/Cloudflare | 不应为展示“在线状态”增加后台网络流量或误报 |
| 独立 AI Provider 管理、重实现 CC Switch | CC Switch 管理 AI 路由，RouteSpan 仅延伸本机能力 |
| root、严格/宽松桥接鉴权、MCP、新工具适配 | 归属后续 v0.3/v0.4 |
| GitHub 仓库、Tauri identifier、数据目录重命名 | 属于另立迁移项目；必须保护旧版自动更新 |

**高级 / 宽窗口：** 可按卡片分组，不必同时展示所有内容；高频操作放顶部，低频表格和手动设置下沉。使用与远程桥接同一外框密度，而不是复刻远程端业务模块。

**窄窗口（包括应用 560px 最小宽度）：** 双列折叠为单列；文字允许折行；端点长文本省略但可复制/查看全称；操作按钮可换行；不存在横向整体滚动。固定标题区与唯一主要滚动容器优先，避免嵌套滚动造成难以操作。

### 3.3 视觉规范

- **一致的组件职责**：标题 `h1`、section `h2`、卡片、StatusIndicator、HelpTooltip、确认对话框与 NotificationCenter 均沿用当前设计体系。
- **主题**：保留温暖橙 / 睿智蓝 / 未来青 / 常规白，均支持明暗模式。已确认三品牌基色：珊瑚橙 `#F89868`、天空蓝 `#70B0F8`、薄荷青 `#80E0D8`。
- **用户明确确认的视觉选择不变**：浅色品牌主题按钮白字、白色环境变量勾选、开关白色圆点等不擅自改动；已记录的对比度例外继续诚实保留。
- **Logo**：只复用 `BrandMark` 和品牌资源，不重绘、不改比例、不染色。
- **状态不能只靠颜色**：颜色旁必须有文字/图标，并区分 `未检测 / 检测中 / 已配置 / 正常 / 需要处理`。
- **禁止新增悬浮全局提示条**：持久业务状态留在所属卡片，操作失败使用既有 NotificationCenter；验证错误紧邻输入项。
- **不要强制追求“完全相同”**：本机重点是活动代理和系统观测，远程重点是 SSH/能力连接；视觉一致不等于相同字段。

## 4. 详细功能设计与验收规则

### F01｜概述与高级切换（P0）

- 本机默认打开“概述”；“高级”用于候选列表、手动配置、环境变量明细、详细诊断。
- 切换视图只改变 UI 呈现，**不触发代理选择、变量写入、SSH 操作或额外联网测试**。
- 页面在全局导航切换期间保持挂载的现有行为；用户在本机高级页返回本机时尽量保持视图，但首次启动默认为概述。
- 与远程桥接的两视图设计语义一致，ARIA 使用 `aria-pressed`/正确选中状态，键盘可操作。

**验收**：切换本机两个视图不影响远程工作区、活动代理 `revision`、当前变量值或应用助手返回路径。

### F02｜活动代理总览（P0）

显示：客户端名与图标、来源（自动/用户选择/系统代理/手动）、host:port、协议、监听可用性、切换入口、复制地址。必要时显示正在刷新/来源不明。

**四种不同事实**：

| 事实 | 含义 | 不能误写成 |
|---|---|---|
| 已选定 | 后端 ActiveProxyContext 当前选择 | 已连接互联网 |
| 正在监听 | 本地端点可连接/检测有监听 | GitHub 或 AI 服务正常 |
| 已应用 | Windows 当前用户环境变量实际匹配 | 系统代理/TUN 已切换 |
| 外网检查通过 | 明确触发的一次测试成功 | 所有应用/所有网络目标永远可达 |

候选客户端不存在或失效时，**保留失效的当前选择及可解释状态**，不自动切换到另一个检测到的程序；仅提示重新选择或重试。当前选中不等于“最后一次扫描排名第一”。

**验收**：零客户端、单客户端、多个同名进程、监听端口变化、手动端点失效都有正确状态，不误显示成功。

### F03｜客户端选择管理（P0）

- 概述显示一个明确“切换代理”入口，高级提供完整的候选客户端列表（名称、图标、监听状态、地址、协议、检测来源）。
- 优先以列表或轻量选择弹层展示，替换当前低可见性的候选翻页控件；支持禁用不可用项与明确选中标记。
- 实际选择调用现有 `select_active_proxy(candidate_id)`，**成功以前不假定后台已经切换**，状态从返回的 `EnvironmentStatus` 更新。
- 不修改 Windows 系统代理；不因选择变化而无确认地同步环境变量；本机与远程通过同一个后端选择权威共享结果。
- 有活动远程桥接时，不宣称“切换本机代理已经让当前远端连接自动无缝切换上游”；沿用远端后端现有机制与校验，必要时提示重新检查。
- 手动端点沿用 `inspectProxyEndpoint` → 检查结果 → 允许用户知情确认 → `syncManualProxyEnvironment`。**此命令既会配置环境变量也会设置手动活动代理**，不得误表述为“只选择”。

**验收**：点击其他候选后，当前选中与环境变量匹配度分开更新；不出现选择 A 却展示 B 地址；快速点击与扫描刷新无串态。

### F04｜系统代理与 TUN 观测卡（P0）

- 复用 `NetworkObservationPanel.vue`；概述采用紧凑卡片，高级保留更充分的帮助说明。
- 显式显示“只读观测”；系统代理关 / 未知 / 可能失效 / 开启、TUN 未检测 / 可能 / 检测到 / 未知均使用已有状态语义。
- TUN 的“possible”不写成“已启用”，系统代理设置不代表当前活动代理，TUN 存在不代表某个进程一定通过它联网。
- 不加入系统代理和 TUN 开关；仅给出观察到的结果和必要解释。

**验收**：只有 TUN、只有系统代理、两者均未知、代理客户端全部关闭时，不制造“本机代理正常”的结论。

### F05｜环境变量总览与管理（P0）

- 概述状态由现有 `EnvironmentStatus.state` 派生：`disabled / partial / enabled / mismatch`。
- 概述展示关键影响、已管理变量数和三种现有动作：**同步当前代理 / 关闭代理环境 / 恢复之前状态**。只有满足原有后端条件才允许执行。
- 高级展示所有环境变量实际值；`HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 勾选表示“**同步后启用这些变量；未勾选或协议不支持的受管变量会被清除**”，**不等于当前已经写入**。`NO_PROXY` 等只读项不能假装受该勾选控制。
- 保留至少选择一种受控代理变量的既有约束、快照存在且通过冲突校验时才可恢复、写入冲突拒绝覆盖等机制。
- 恢复/关闭等危险动作继续遵循现有后端事务；失败必须反馈原状态或重新刷新后的可靠状态，不做前端虚假乐观成功。
- 显式提示：用户环境变量主要影响**之后启动的进程**，已打开的终端和编辑器通常不会自动继承变化。

**验收**：disabled / partial / enabled / mismatch 四态在概述与高级一致；手动端点与自动同步均不会悄悄覆盖与活动代理无关的设置。

### F06｜代理连通性检测结果卡（P0：本版关键新增）

**已有后端**：

- `test_current_proxy_connectivity(expected_revision: u64)`：基于当前活动代理，检测本地监听、协议，然后经所选代理请求 Google / GitHub / Cloudflare；有超时与分目标结果。
- `get_last_proxy_connectivity_result()`：读取后端缓存，不请求外网检测目标；本机候选刷新可能执行监听/协议探测；缓存 TTL 5 分钟，按活动候选标识/端点匹配；用户可主动重新测试。
- 后端 `active::with_current(Some(expected_revision), ...)` 在检测调用前后检查活动代理版本，防止测试过程中选中项变化导致错误接受。

**前端 API 和类型约定**（以真实 Rust `serde(rename_all="camelCase")` 为准）：

```ts
// src/shared/types/index.ts
export type ProxyConnectivityState =
  | "notTested" | "testing" | "reachable" | "partial"
  | "unreachable" | "localProxyUnavailable" | "unknown";
export type ConnectivityErrorKind =
  | "proxyUnavailable" | "proxyHandshakeFailed" | "connectTimeout"
  | "tlsFailed" | "remoteRejected" | "httpStatus"
  | "networkError" | "unknown";
export interface ConnectivityTargetResult {
  name: string;
  url: string;
  success: boolean;
  statusCode: number | null;
  durationMs: number | null;
  errorKind: ConnectivityErrorKind | null;
}
export interface ProxyConnectivityResult {
  state: ProxyConnectivityState;
  endpoint: ProxyEndpoint;
  localListenerOk: boolean;
  protocolOk: boolean;
  targets: ConnectivityTargetResult[];
  testedAt: string;
  totalDurationMs: number;
}

// src/shared/api/backend.ts，示意签名；实现以现有 invoke 命名规范为准
// testCurrentProxyConnectivity: (expectedRevision: number) =>
//   invoke<ProxyConnectivityResult>("test_current_proxy_connectivity", { expectedRevision }),
// lastProxyConnectivity: () =>
//   invoke<ProxyConnectivityResult | null>("get_last_proxy_connectivity_result"),
```

**交互约束**：

1. 默认显示“未检测”。页面加载时允许读取一次**已有缓存**，但不得为了填卡片而自动执行测试。
2. 点击 **测试连接**：读取当前后端活动代理 `revision`，标记测试中的 request ID / selection revision，再调用后端测试；按钮防重复触发。
3. 回包时先检查测试仍属于当前选中代理（revision + 必要的端点身份校验），否则**丢弃过期结果**；不能让原代理 A 的成功结果更新新代理 B 的卡片。
4. 展示本地监听、协议匹配、总体 `reachable / partial / unreachable / localProxyUnavailable / unknown`，以及分目标成功/失败、耗时、必要的错误类别。
5. `partial` 必须明确表示“部分测试目标成功”，不能当作“所有网络正常”；全部失败也不能无限推断上游原因，应提示逐层诊断。
6. 切换代理或失效时清除/标记当前显示的旧结果。单次手动测试并不形成长期健康监控。
7. **取消检测的限制**：现有 Rust 命令无真实 Abort API。若 UI 提供“停止显示/取消等待”，只能忽略后续回包，**不得宣称底层请求已被取消**；真正取消要另做支持和测试。首版可只提供检测中状态和有限等待。
8. 结果属于局部诊断，不包含敏感 Token、浏览器历史、系统环境全量信息；诊断报告沿用现有脱敏策略。

**验收**：未测试、监听失败、协议异常、单目标成功、多个目标成功、请求超时、切换期间回包、缓存过期均可稳定显示；不新增外网轮询。

### F07｜失效感知与恢复建议（P1）

- 复用现有周期性的**本地状态读取**，避免另开轮询链路；这不是新增外网探测。
- 客户端关闭、端口变化、系统代理指向失效端点：状态文字准确，提供**重新扫描 / 选择其他代理 / 重新同步**等有意义的可执行入口。
- 用户手动选择的代理失效时，后台不自动改为其他候选项；用户通过显式点击决定后续操作。
- 检测结果异常不等于必须断开 SSH；远端既有行为保持后端权威，不从本机 UI 直接操纵远端状态。

### F08｜应用助手入口整理（P1）

- 概述底部采用类似 `BridgeLaunchBar.vue` 的明确主操作样式，按钮为**打开应用助手**。
- 继续进入已有上下文 Application Assistant，不把已有多步骤诊断塞进概述卡片，也不新增独立页面层级。
- 应用助手原有代理/直连启动、重启、规则预览、授权及恢复机制全部保持，禁止未经需求确认重构。

### F09｜反馈、可访问性和多语言（P1）

- 使用 `NotificationCenter` 展示瞬时操作结果；状态卡保留稳定原因；输入非法反馈就地展示。
- 四语言 zh-CN/en/ja/ko；长日文/德文式长名称及路径模拟均不溢出。普通 UI 不露出 Rust 错误原文或隐私文件路径。
- 保留键盘 Tab 顺序、focus visible、屏幕阅读器状态文字；测试进行中使用 `aria-busy`，结果区域避免高频 `aria-live` 重复播报。
- 系统减少动态效果生效；禁止新增大量动画干扰本机网络管理。

## 5. 状态矩阵与操作约束

| 情景 | 概述显示 | 主操作 | 禁止行为 |
|---|---|---|---|
| 未检测到代理 | 无可用活动代理；系统代理/TUN 仍独立展示 | 刷新、手动端点、应用助手直连路径 | 假装代理正常 |
| 检测到多个客户端 | 当前选中明确标记，候选数可见 | 切换代理 | 按扫描排名后台切换 |
| 当前代理停止监听 | 当前选择失效，地址保留作参考 | 重新扫描、选其他客户端 | 自动迁移到陌生端口 |
| 系统代理有效但未选为活动代理 | 独立系统代理观测 | 显式选择 | 把系统代理直接当“当前已应用” |
| 仅检测到 TUN | TUN 可能/已检测（按证据） | 引导检查本机代理 | 将 TUN 观测当代理入口 |
| 环境变量已启用但端点不一致 | mismatch 和风险说明 | 同步当前代理 / 检查原配置 | 静默覆盖、称正常 |
| 代理已选且监听，未做外网测试 | 监听正常 + 外网未检测 | 测试连接 | 显示外网已通过 |
| 检测只有一个网站成功 | 部分通过，列出失败目标 | 重新测试 / 查看详情 | 宣称整个代理不可用或完全正常 |
| 代理切换时旧结果回包 | 保持新代理状态，丢弃旧回包 | 重新测试 | 把旧地址结果赋给新代理 |
| 当前有远程 SSH 连接 | 本机所选状态真实同步 | 可按原能力选择，但后端负责校验 | 前端直接改 SSH 转发/绕过验证 |

## 6. 架构与组件拆分建议

仅建议拆分**本机 UI 视图**，不要因为整理页面而分裂后端的活动代理 Store。

```text
src/features/proxy/
  components/
    ProxyPage.vue                  # 页面容器、视图切换、子组件编排
    LocalProxySummary.vue         # 概述中的活动代理（建议新增）
    LocalProxyCandidates.vue      # 高级的代理候选列表（建议新增）
    LocalEnvironmentCard.vue      # 变量状态及操作按钮（建议新增）
    LocalConnectivityCard.vue     # 测试按钮、结果摘要、详细结果（建议新增）
    LocalProxyManualDialog.vue    # 现有手动端点逻辑拆出；需保留原确认语义
  connectivity-presentation.ts    # 可选：纯状态映射，便于单测
```

> 文件名是建议，不是要求一次新增所有组件。若抽象造成双重状态或不必要的 Props 转发，优先少拆、易审查。原有 `NetworkObservationPanel`、应用助手、全局通知和通用状态组件尽量复用。

**组件间数据原则**：

- `AppShell.vue` 是后端数据和 mutation 的接线层；`ProxyPage` 是本机界面协调层；子组件以 Props 显示、Emit 发动作，不独自创建另一套真实活动代理状态。
- 对 `activeProxy`、`environment`、`candidates` 的后端返回采用既有 `acceptEnvironmentStatus`（含 revision 检查）。
- 视图状态（概述/高级、局部弹层、表单输入、展开）可以在本机组件中管理；不能与后端业务权威混淆。
- 对话框保持取消可恢复；手动端点校验与最终用户确认不因 UI 重构而消失。
- 页面更新时避免重新挂载 RemoteBridgePage、破坏远端连接或应用助手选择。

## 7. Milestone 实施顺序与完成标准

### M0｜基线审计、页面设计与预览（必须首先执行）

任务：

- 确认工作树干净、远程 main 的最新 SHA、当前 CI 状态及 v0.2.1 的发布事实；从最新 main 创建新的 v0.2.2 开发分支（例如 `v0.2.2dev`），不要在 `v0.2.1dev` 继续开发。
- 盘点本机每个现有入口、动作及后端命令。制作旧版 → 新版映射表，列出任何看似可删除但仍被其他功能使用的动作。
- 确认概述/高级的线框与窄窗口样式，可使用明确 Mock 的浏览器 UI 预览，但不能把预览值混入真实 Tauri 安装包。
- 先运行完整现有测试并记录基线结果；记录仓库与本文差异；本次评估已确认的缺口直接按修订实施，只有新增范围或产品行为决策才需要维护者确认。

**M0 DoD**：布局/状态/操作矩阵可审；本阶段原则上不改 Rust 核心、不改发行版本、不发 Tag。

### M1｜工作区布局与视觉统一

任务：拆分/重组 `ProxyPage.vue`；概述/高级；标题、工具栏、卡片、应用助手入口；复用远程组件设计规律；适配 560px 最小窗口。

**M1 DoD**：纯 UI 重排后，代理选择/变量写入/手动确认/导航与既有 v0.2.1 行为一致；不同主题无错版。

### M2｜候选代理与变量管理

任务：清晰的切换列表、代理失效表达、手动端点表单/确认、变量状态卡及详情、操作反馈。

**M2 DoD**：后端选择权威不变；不会自动选其他代理；变量快照/恢复逻辑和冲突保护通过回归。

### M3｜连通性检测接入（功能增量）

任务：前端类型与 API、卡片、状态纯函数、请求 ID/revision 防串态、后端缓存读取、详细结果、四语言文案。

**M3 DoD**：真实 Rust 命令被调用且结果可视化；不主动外网轮询；旧代理测试结果不覆盖新代理；浏览器 Mock 和真实 Tauri 严格隔离。

### M4｜状态一致性与体验收尾

任务：修复多代理、端口改变、客户端重启、刷新失败、慢请求、空状态、窄窗口和应用助手来回切换的缺陷。仅对确认的 Bug 改 Rust 并补最小单测。

**M4 DoD**：所有 P0/P1 功能和错误路径已覆盖；没有引入新权限或新增不受控自动恢复行为。

### M5｜发版预检与发布交接

任务分为两段：开发预检完成源码测试、安全审计与候选发布记录；获得发版授权后，再统一更新版本/发布说明/契约断言，运行 CI、构建签名包，并执行 Windows 安装升级和外部产物核验。

**M5 DoD**：开发验收 Gate 达标，报告剩余限制，**等待维护者授权才创建稳定 Tag**；Tag 触发 Draft 构建后还需单独完成外部签名/校验值/安装验收，才能由维护者决定公开发布。

> **提交建议**：`docs(local): freeze v0.2.2 workspace spec` → `refactor(local-ui): align overview and advanced layouts` → `feat(local-ui): improve proxy selection and environment cards` → `feat(local): show existing proxy connectivity diagnostics` → `test(local): cover state races and layout contracts` → `chore(release): prepare v0.2.2 preflight`。这些只是建议，不要求强行拆碎一组不可独立测试的修改。

## 8. 自动化与真机测试矩阵

### 8.1 自动化（最低要求）

- 现有 `pnpm build`、`pnpm check`、Rust fmt/clippy/test、前端/Rust 依赖安全审计均正常；若 `pnpm check` 已包括子项，CI 不重复浪费执行时间。
- 新增本机 UI/状态测试，例如 `scripts/test-local-workspace.mjs`、`scripts/test-local-connectivity.mjs`，并接入 `pnpm check` 和 GitHub CI / Release Workflow。测试名称以仓库现有规范为准。
- 纯函数用真实 DTO 和状态表验证“未检测/partial/timeout/错误类别”；mock 中的无效请求、快速重复点击和页面返回必须可测。
- 关键竞态：A → B 切换时 A 检测返回、重复刷新、按钮重复点击、后端 revision 变化、窗口后台返回、网络检测报错后再测试。
- 非 UI 契约：代理选择单一来源、远程仍读取同一选择、环境变量 snapshot 和回滚、现有 `ApplicationAssistantPage` 工作流。
- CI/发布契约：保证版本号一致、Updater 地址/公钥/包身份不变、多语言发行说明结构正确，`targetVersion` 不停留在 `0.2.1`。

### 8.2 Windows 真实环境

| 维度 | 最低用例 |
|---|---|
| 系统 | Windows 10/11 x64，正确记录版本；WebView2 正常 |
| 主题 | warm/blue/teal/neutral × light/dark，并测试跟随系统模式 |
| 窗口 | 560px 最小宽度、880px 默认宽度、常用最大化；100%/125%/150% DPI |

| 变量 | disabled/partial/enabled/mismatch；勾选管理项、应用、关闭、冲突、恢复 |

### 8.3 不接受的“假通过”

- 浏览器 Mock 成功不能代替 Windows 安装包测试。
- “代理端口能连接”不能代替真实外网测试；“一个网站失败”不能自动判定代理完全失效。
- 组件截图不等于执行了环境变量操作或能恢复旧快照。
- 打包成功不等于签名、真实升级及已发布 latest.json 全链路验证成功。
- 不得为通过测试而关闭审计、禁用签名或放宽已有安全约束。

### 已知风险

1. **UI 调整影响远端**：全局 CSS class 可能被两个工作区共享；尽量限定 `.local-workspace` 范围，必要时用新的局部 class。
2. **代理选择/刷新竞态**：后端 revision 已存在；前端还需 request ID 和当前选择校验。
3. **连接检测误报**：检测目标受网络、地理位置和防火墙影响，展示分项事实，禁止把单站状态写成整体网络绝对结论。
4. **环境变量不可恢复**：保持后端 snapshot/restore 的原子性与冲突检测；不引入仅靠前端缓存的恢复功能。
5. **发布版本固定断言**：测试中仍指向 v0.2.1 的地方需在 M5 全面检查；不能早改版本导致开发中的正式流程状态混乱。
6. **旧版兼容**：v0.2.2 不修改用户存储结构、不引入未知设置字段、不变更包名与更新链路。
