## 冻结文件生命周期设计

当前 `FrozenProfile` 校验渲染内容和路径字符串。正式接线需要额外持有目录与文件对象的句柄，将校验结果绑定到 OpenSSH 通过路径打开的同一组对象。[FrozenProfile 源码](../../src-tauri/src/features/remote_bridge/target_os/windows_bridge/safety/frozen.rs)

| 阶段 | 拟议保证与退出条件 |
| --- | --- |
| 定位私有目录 | 用当前进程令牌 SID 和 Windows 本机应用数据目录定位受管根。首版只考虑经验证的本地 NTFS 路径。为每次尝试生成随机子目录，创建时应用显式、受保护的 DACL，授予当前用户及部署确有需要的系统主体最小权限。核对所有者、有效权限及父目录是否允许其他用户替换；拒绝网络盘、重定向到未知卷、未验证的共享根和宽权限。 |
| 固定完整路径 | 从已核验的根逐级打开目录，使用 `FILE_FLAG_BACKUP_SEMANTICS` 和 `FILE_FLAG_OPEN_REPARSE_POINT`，逐项校验实际卷、文件 ID、类型和重解析属性。用排除 `FILE_SHARE_DELETE` 的持有句柄固定参与解析的目录；打开后再确认句柄关系和实际路径。单次规范化字符串或只检查末级路径不足以覆盖父目录替换。发现 junction、symlink、重解析点、跨卷对象或不能固定的组件即拒绝。 |
| 创建和固定三份文件 | 只在这次已固定的目录内以 `CREATE_NEW` 写入固定文件名。校验文件为普通数据流、无重解析标记、硬链接数为 1，记录卷 ID 和文件 ID。写入并刷盘后，拟在关闭写句柄前建立一个禁止删除的读取句柄。关闭写端后再以只允许 `FILE_SHARE_READ` 的方式建立最终读取句柄，复核相同 ID、ACL、链接数及完整字节，再交给进程启动阶段。中间阶段不启动进程。最终读取句柄须全程保留，若有未释放写句柄或对象变化导致分享校验失败则撤销本次尝试。 |
| 启动与兼容性 | 使用已验证的 OpenSSH 可执行文件和固定 argv，将 `-F`、`UserKnownHostsFile`、`RevokedHostKeys` 指向已固定对象。挂起创建、确认 Job 归属、复核对象和策略后恢复主线程。只读共享必须兼容目标版本实际打开这三份文件的行为，路径含空格时也须相同。先用合成配置检查解析，再在获准环境验证真实读取，覆盖撤销文件为空、不可读和命中撤销的情况。遇到分享冲突停止本次接线。 |
| 失败和退出 | 禁用入口并关闭已有流量，关闭 Job、回收进程及管道，再释放配置只读句柄。在仍固定的受管父目录内重开删除句柄，核对创建时 ID、所有者及类型后，按句柄删除本次已记录的文件和空目录。无法证实对象身份时保留待清理记录。异常退出后的清理只检查有来源记录的目录，拒绝沿重解析点走访或递归删除未知内容。 |

此设计约束不同 Windows 账号和路径替换。普通桌面进程与同一个 SID 下可控制本进程的代码共享信任边界，需要独立主体才能防护后者。
实际 ACL、祖先目录句柄、写转只读的共享交接、删除语义和受支持 OpenSSH 版本均须实测后才能用于正式接线。

## 握手身份与原有信任

`ssh::VerifiedHostIdentity` 当前只由测试构造。后续唯一生产签发入口应在受控 OpenSSH 执行器内部。[SSH 源码](../../src-tauri/src/features/remote_bridge/ssh.rs)

1. 从绑定目标取得有效主机、账号、端口和配置指纹，使用独立审查的单一普通 Ed25519 公钥，并完成下述信任来源核对。保护真实二进制路径、冻结文件、argv、进程句柄和会话代次。
2. 启动无转发的认证探针。固定探针在受认证通道上返回当次随机挑战，客户端校验完整回执及成功退出，再复核目标、进程和冻结证据。由执行器私有入口签发身份，绑定本次连接用途、进程、主机密钥、冻结对象和会话代次。调试输出、远端自报指纹、`ssh-keyscan` 和既有 M2 结果均无签发资格。
3. 转发连接与监听复核分别进行新的 SSH 握手。前一次身份只能建立计划所需的证据，不能替下一连接作证。转发连接还须让绑定该次进程和入口的单次回执实际经过当前路径。任何条件缺失直接结束本次尝试。

有效信任集合须从用户与组织实际使用的 OpenSSH 选项和文件完整推导。核对真实主机匹配规则、端口、别名、IP 检查、算法要求、全局与用户 `known_hosts`、普通及哈希条目、`@revoked`、`@cert-authority`、独立撤销文件和 KRL，以及 DNS、外部命令和连接复用选项的影响。读取配置前处理 `Include` 和 `Match exec` 的副作用风险，遇到无法静态证明安全的配置即拒绝。

首版只接受独立审查的普通公钥已在原有效信任集合中且不违背任何更严格规则的目标。可冻结等效的全局和用户信任快照，或在有完整等效证据时收敛成唯一公钥及全部适用撤销约束。仅在证明全局文件的约束已经完整保留时才可使用 `GlobalKnownHostsFile none`。要求 CA 或证书、有不支持的撤销或外部约束、来源不可读取或文件变动时，拒绝目标并使旧绑定失效。
[OpenSSH 主机密钥校验](https://man.openbsd.org/ssh#VERIFYING_HOST_KEYS) · [全局信任文件](https://man.openbsd.org/ssh_config#GlobalKnownHostsFile) · [撤销规则](https://man.openbsd.org/ssh_config#RevokedHostKeys) · [OpenSSH 密钥交换验签源码](https://github.com/openssh/openssh-portable/blob/V_9_5_P1/kexgen.c#L190-L207)

## 撤销、最大序号和会话到期

`policy.rs` 已校验签名、期限及调用方提供的 `seen_status_sequence`。实时撤销状态读取和持久化仍待接线。[策略验证源码](../../src-tauri/src/features/remote_bridge/target_os/windows_bridge/safety/policy.rs)

1. **权威最新状态。** 通过被许可 SSH 路径之外的独立、已认证管理通道查询。签发方为每个审查修订及部署维护单调序号，以固定签发密钥签署最新状态、用途、本次随机挑战和有效期。拒绝缺失、错误签名、旧序号、同序号不同决定、超时或无法确认权威来源的响应。随机挑战绑定本次查询，离线缓存不准创建或延长会话。
2. **本机最大序号。** 以签发密钥标识、审查 ID、修订和部署为索引，保存已见最大序号及其决定摘要。使用用户 SID 限制的 DACL 和当前用户 DPAPI 保护，跨进程以受控锁串行读写。在同一受管卷原子提交并刷盘，提交较高序号成功后才发放许可，包括撤销决定。损坏、缺失、较低序号和并发冲突均停止使用旧状态。新登记须先确认独立审查和权威最新响应，禁止拿空状态恢复已登记会话。
3. **反回滚依据。** 本机 DACL 与 DPAPI 保护访问和篡改检测，无法单独识别整份存储被回滚。每次创建会话和续期须获得绑定新挑战的权威最新响应。权威端也要验证序号存储的恢复行为和签发一致性。重新登记或签发密钥、审查修订、部署代号变更需独立审批后再建立新作用域。
4. **硬截止。** 会话管理器在通道外维护策略失效计时，使用许可、撤销状态及现场约束中的最早截止，同时复核墙钟、单调时钟以及睡眠恢复。更新失败、撤销、超时、目标变化或所有权无法确认时，先禁止新流量并关闭现有流量，再结束 Job、取消待处理管道 I/O、等待退出和清理文件。到期停用无需依赖 SSH 输出或远端应答。服务器配置变更仍要求先撤销所有许可并确认旧会话与转发已结束。
