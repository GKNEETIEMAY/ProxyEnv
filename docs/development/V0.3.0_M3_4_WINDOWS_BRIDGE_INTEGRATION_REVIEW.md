## A 资源所有权

离线 `LocalRuntime` 继续使用原 `Task`、授权生命周期和冻结文件。桥接传输与托管终端各有独立的 `OwnedProcess` 和 Job。M3.3 的单独终端夹具将进程放入终端槽，缺少传输 Job 时无法通过桥接验证。关闭或发现托管终端退出后只结束该终端。传输失效、授权失效和会话关闭清理两类资源。旧任务的回执和关闭调用必须先通过当前所有者核对。

全会话退出共享原有绝对截止，先关终端再关传输。保留各 Job 的退出报告，两个 Job 确认排空后才清理冻结文件。未排空或文件仍受保护时返回原有未完成清理记录。每个离线任务只接受一次托管终端启动，关闭后需要新任务。M3.4 的离线资源模型继续与生产 Store、Tauri 生命周期及公开调用边界隔离。[运行时资源](../../src-tauri/src/features/remote_bridge/target_os/windows/bridge/safety/runtime/local.rs) · [托管终端](../../src-tauri/src/features/remote_bridge/target_os/windows/bridge/safety/runtime/local/managed.rs)

## B 平台分派与 IPC

`remote_bridge_probe_target_os` 保留原有的 `status`、`shell` 和 `reason` 字段，附加 `targetId`、`platform` 和可选 `windowsBridge`。Linux 使用有界的固定 `uname -s` 输出，Windows 使用 M2 原有强验证探针。未知平台和已确认不受支持的平台分开表示。Windows 状态同时返回桥接传输和托管终端两项不可用。

普通 Linux 载荷及反向转发在取得明确 Linux 证据后使用原入口，并重新核对绑定目标。交互式连接在创建转发前也要求该证据。原认证检查仍使用带平台守卫的只读检查命令，保留既有提示和回执。使用现有 SSH 认证来源，常规 Linux 操作会增加一次只读探测的 SSH 往返。26 项冻结载荷及原脚本字节契约保持一致，真实设备上的时延和不同 SSH 配置组合在 M5 验证。

`Summary.targetPlatform` 和 `Summary.windowsBridge` 为可选字段。已有生产传输快照可公开 Linux 平台。Windows 生产路径只提供只读探测及不可用投影，IPC 无法签发测试身份、批准测试授权或启动本机夹具。Report、Tray 和原代理、AI 能力的独立路径沿用同一 Store。

## C 界面

## D 验收

本机截图与原始测试日志写入 `artifacts/v0.3.0/M3.4/`。启动本机 Vite 后可运行 `node scripts/test-windows-bridge-ui.mjs`，用 `PROXYENV_LAYOUT_URL` 指定本机地址，用 `PROXYENV_LAYOUT_BROWSER` 指定 Edge。Windows 浏览器用例通过合成 IPC 提供平台、SSH 认证错误和生命周期回执，并校验四种语言的关键状态文案。最终截图复验时，本机 Vite 请求超时，因此用 Playwright 拦截并加载隔离的 Vite 开发构建产物，仍由 Edge 渲染真实 Vue 组件。Rust 用例使用当前任务的本机 Job 和合成授权。两种夹具均不连接远端设备。[浏览器夹具](../../scripts/test-windows-bridge-ui.mjs)

新增 Rust 测试覆盖 IPC 序列化、未知/不支持平台拒绝，以及托管终端单独关闭、授权到期和传输进程退出时关闭两个 Job。应用退出原夹具在全量并行中两次把已退出进程归类为强制关闭。Windows 进程句柄收到退出信号后，Job 的活动计数仍可能尚未归零。正常退出场景现在以有界 Job 观察句柄确认排空，再进入关闭步骤，保留原有正常、强制及超期断言。修正后五轮单项复验通过，生产收尾期限和逻辑维持原值。[进程观察](../../src-tauri/src/features/remote_bridge/target_os/windows/bridge/safety/owned_process.rs) · [应用退出夹具](../../src-tauri/src/features/remote_bridge/target_os/windows/bridge/safety/tests/runtime_regression.rs)
