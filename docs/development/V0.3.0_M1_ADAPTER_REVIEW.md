## 接口和职责

| 入口 | 职责 |
| --- | --- |
| `target_os::TargetOs` | 内部枚举 `Linux`、`Windows`、`Unknown`。SCP 前使用固化的只读 `uname -s`。只有明确的 `Linux` 响应通过 `require_linux()`，其余结果报 `remoteUnsupported` 或保留 SSH 传输错误。 |
| `target_os::linux` | Linux stdin 命令、既有 shell 和 Node 助手的载荷及响应解析、交互预检和隧道命令、托管终端和环境命令、Skills 暂存路径。 |
| `ssh`、`ssh_auth` | OpenSSH 参数、进程、超时、凭据、PTY 认证状态与输送。通过 `linux` 模块构造和解析现有远端操作。 |
| `ssh::prepare_skill_upload` / `LinuxSkillStage` | 只读探测通过并收到原 Skills 脚本的 `prepared: true` 后记录暂存状态，绑定本次目标、OpenSSH 配置指纹和 Skills 请求。SCP 在构造命令时复核指纹。 |

`remote.sh` 和 `skill-remote.sh` 先在执行它们的同一远端进程检查 `uname -s`，再进入配置或文件操作。
扩展助手在进入文件事务前检查 `process.platform`。SCP 是单独启动的写入通道，所以在每次 Skills 暂存批次前
加入一次经现有 SSH 验证的只读探测，并要求既有准备操作成功。探测失败或系统不明时拒绝 SCP 上传。
托管终端仅从已准备的 Linux 环境上下文取得命令，手动终端仍由既有通用 SSH 入口处理。

`Windows` 分支当前统一拒绝，`Unknown` 同样拒绝。`Windows_NT` 仅供固定探测输出分类，普通 Windows SSH
环境可能没有 `uname` 而直接得到 SSH 错误。正式 Windows 识别、PowerShell、Windows 网络桥接与工具写入属于后续里程碑。
没有 IPC、前端选项、用户配置字段或持久目标系统缓存。

## 风险和回滚

- SCP 每批 Skills 暂存多一次经 SSH 验证的只读命令，有独立超时。远端 shell 包装器、额外 stdout 或受限命令可能导致拒绝上传，需要在真实 Linux SSH 设备复核。
- 独立的 SSH 探测、准备与 SCP 仍是不同进程。配置指纹核对能发现有效 SSH 配置变化，目标身份依靠现有 OpenSSH 主机密钥校验。无设备证据时不扩大保证范围。
- picomatch 公告已撤回，项目继续跟踪无正式补丁及已观察到的 glob 性能风险。见 [M0-Fix2 Review](M0_FIX2_REVIEW.md)。
- 回滚可单独撤销 M1 提交，恢复原 Linux 调用路径和 SCP 行为；M0-Fix2 证据提交可保留。没有数据迁移。
