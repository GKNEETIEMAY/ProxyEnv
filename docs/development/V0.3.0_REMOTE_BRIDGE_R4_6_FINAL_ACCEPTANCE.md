| --- | --- |
| 正常完成和重复回执 | **PASS**。合成认证通过真实状态解析和移交，桥接成功。重复 `finish` 返回 `sshAuthSessionMissing`。后续断开只释放一次假传输 |
| 在会话表中取消 | **PASS**。会话取消后无法完成，资源释放一次 |
| 会话移出表后取消并断开 | **FAIL**。通道暂停已经拿走认证会话的线程。旧 ID 的取消返回 missing。断开已发布 Disconnected 后放行，旧完成重新取得 Store 并回到 Connected |
| A → B 设备切换 | **FAIL**。A 已拿走会话时启动 B，放行 A 后 A 先取得 Store。B 的完成返回 `alreadyConnected`，B 的假资源被释放 |

认证入口在移出 Sessions 后可能写缓存。提交仅检查目标指纹、适用的代理修订及当前子进程，缺少待交互意图的会话 ID 与代次校验。本机夹具显式关闭密码缓存资格，未测量缓存写入。建议为认证交接携带会话 ID、目标/配置指纹与连接代次。在同一个提交边界验证停止、取消及断开状态，再授权更新凭据、接管传输和发布状态。以旧完成拒绝、原资源恰好释放一次、B 仍可成功作为独立修复验收。[认证完成](../../src-tauri/src/features/remote_bridge/ssh/ssh_auth.rs#L992) · [交互提交](../../src-tauri/src/features/remote_bridge/mod.rs#L2337)

## V3 原生应用退出

外部观察进程在关闭前拿到两个测试子进程的同步句柄，确认子进程存活、独占文件锁被持有且 Relay 可连接。等待应用 PID 退出并检查退出码后，才验证子进程句柄已终止、文件锁可重新获得、环回监听已经关闭。三种场景都重复调用了关停入口。

| 场景 | 回调中的 Report / Tray | 进程结束后的观察 | 结论 |
| --- | --- | --- | --- |
| 无争用关闭 | Disconnected / Disconnected | 清理线程完成。主、附加资源的析构完成标记都存在，两个占有文件均已清除 | **PASS** |
| 已接纳后台任务且主析构仍等待 | Disconnected / Disconnected | 主析构开始后未完成，附加析构未开始，清理线程未完成。两个占有文件仍在。两个测试子进程、锁和监听均已释放 | **FAIL**，应用层清理不完整 |
| Store 跨过回调等待窗口仍被占用 | Connected / Connected | 清理线程未接管 Store，两个析构均未执行，两个占有文件仍在。两个测试子进程、锁和监听均已释放 | **FAIL**，应用层清理和终态均未完成 |

Windows 的被测 Job 所辖子进程随父进程退出而结束。占有文件用于观察析构是否执行，属于临时合成资源。这些结果仅覆盖被观测的 `OwnedChild`、附加资源和本机 Relay。生产事件循环、真实交互 PTY、管道进程树的最终终止仍为 **PENDING**。200 ms 是回调的等待窗口。它能保护回调返回，无法保证进程终止前收齐应用层清理回执。[退出回调](../../src-tauri/src/lib.rs#L142) · [桥接关停](../../src-tauri/src/features/remote_bridge/mod.rs#L2608)

建议单独在应用的退出请求与最终退出之间加入有期限的关停协调。先停止接纳并撤销当前连接意图，再等待明确清理回执。超期结果需显式记录，且应验证受测进程、管道和会话资源均采用可证实的终止或后续清理路径。保留现有 Store 和资源所有权。
