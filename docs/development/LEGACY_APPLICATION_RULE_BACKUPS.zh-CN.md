## 审计结论

v0.2.2dev 移除了旧应用助手的规则写入、备份恢复、无代理启动及强制重启接口。**升级不会自动复原旧版曾修改的第三方应用配置，也不会删除旧备份。** 新页面的“带代理变量启动”只构造新进程环境，不读取或写入这些备份与应用配置文件。

有一个重要的范围限定：v0.2.1 Tag 的 `src-tauri/resources/app-rules/` **仅包含 `schema.json`，没有可执行的应用规则**；`build.rs` 又明确排除了 `schema.json`，因此该 Tag 的标准构建规则目录为空。旧写入接口必须先匹配一条内置规则，无匹配时返回 `previewUnavailable`，无法通过标准界面产生规则改动。此结论来自源码与 Git 树，不等同于逐一检查所有安装包或用户磁盘。自行增添规则的开发构建、其他历史版本及外部产生的文件仍需单独判断；不能仅凭目录存在认定它是可信备份。

## 真实路径、命名和格式

Windows 来源为 `dirs::data_local_dir()` 下的兼容目录：`%LOCALAPPDATA%\ProxyEnv\app-rule-backups\<id>.json`。不属于环境变量快照，也不属于远端 `~/.proxyenv` 数据。

`id` 由毫秒时间戳、进程 ID、序列号构成，以 `-` 分隔；旧读取器仅接受不超过 96 字符的数字/连字符 ID，文件名 ID 必须与 JSON 内 `id` 一致。旧读取上限为 1 MiB，使用安全文件读取，不应跟随符号链接或重解析点。

JSON 字段如下，均为 camelCase：

| 字段 | 含义与检查 |
|---|---|
| `id`、`ruleId` | 文件标识和来源规则 ID；必须能对应可信的旧构建与规则，不能把任意 JSON 当作规则 |
| `targetFile` | 原配置绝对路径；只允许对应旧规则声明的路径及当前用户允许的根目录，路径改变时不得猜测新目标 |
| `fieldPath` | JSON/YAML/TOML 的字段层级，或 INI 的 `[section, key]`；必须与来源规则一致 |
| `oldValue`、`appliedValue` | 修改前和修改后的**单个字段值**，可能为字符串、数字、布尔或 null；不是整份文件备份 |
| `beforeHash`、`afterHash` | 当次写入前/后整个文件原始字节的 SHA-256，小写十六进制；不能根据字段值重建原文件，也不能用 hash 证明备份来源真实 |
| `createdAt` | RFC 3339 时间；只能辅助核对时间，不能代替来源核验 |

旧恢复实现检查规则唯一、字段选择器和目标路径一致、当前字段仍等于 `appliedValue`，再将该字段改回 `oldValue`；写入前后校验当前文件哈希以拒绝并发改写。它**不要求**当前整份文件一直等于备份的 `afterHash`，也不会因为恢复成功而删除该备份。因此“存在备份”不能证明改动仍未恢复。

## 判定矩阵

| 情况 | 判定 / 处理 | 本轮证据 |
|---|---|---|
| 标准 v0.2.1 构建，无有效规则 | 无旧规则可执行，不需迁移入口 | Tag 源码和规则清单已核对；未对安装包逐个取证 |
| 无备份或字段已经等于 `oldValue` | A：无需从该备份恢复；无备份不能排除其他工具的改动 | 源码审计；未提供用户样本 |
| 完整备份、来源可证明、路径/规则一致，当前文件 hash 与 `afterHash` 一致且字段等于 `appliedValue` | B：可按下一节进行人工字段恢复 | 条件说明，真实/脱敏样本未验证 |
| JSON 损坏、ID/字段不符、未知来源、目标文件缺失 | C：停止，不猜测旧值或目标 | 旧版校验逻辑已审计；用户样本未验证 |
| 配置已被外部修改、hash 不符、路径改变或应用正在写文件 | C：拒绝自动恢复；交维护者比对，保留双方数据 | 用户样本未验证 |
| 权限拒绝、只读、重解析点或目标超出允许目录 | C：停止，不提升权限、不重定向到其他路径 | 用户样本未验证 |

## 人工安全恢复步骤（仅适用于 B）

1. 完全退出受影响应用，确认它没有后台进程继续保存配置。先复制当前配置和旧备份到用户控制的安全目录；保留原文件，避免同步或编辑器自动格式化。配置与备份可能含敏感值，不要贴到公开 Issue。
2. 从确切来源构建核对规则、文件名 ID、JSON `id`、`ruleId`、`targetFile`、`fieldPath` 及字段类型。此任务没有提供任何真实或脱敏样本，无法确认来源时停止，交维护者审核。
3. 对当前目标的原始字节计算 SHA-256，并与备份 `afterHash` 核对；再用支持对应格式的本地编辑器查看字段，确认仍为 `appliedValue`。任一不符均停止：即使旧恢复器允许无关字段变化，本指引也不代替人工冲突审查。
4. 仅将已存在的指定字段从 `appliedValue` 改为 `oldValue`，保持原类型、编码和其他字段。不要把整个 JSON 备份覆盖到目标文件，也不要对目录批量替换。null、删除字段、格式损坏等语义不清时停止。
5. 保存后确认文件仍能被应用解析，指定字段等于 `oldValue`，其他设置没有改变；重新打开应用验证。若出现异常，退出应用后使用第 1 步的当前配置副本恢复，并保留现场供维护者核对。旧备份继续保留。

没有来源规则或不能安全确认字段时，不建议盲目降级调用旧接口：标准 v0.2.1 不内置规则，旧接口也不会接受无法匹配的备份。确有历史用户样本时，应另行设计限定路径、只读预览、冲突拒绝和显式确认的恢复任务。

## 未验证项与边界

本次未扫描用户备份目录、未修改第三方配置、未执行真实恢复，也未提供写盘恢复 IPC。安装/升级是否保留目录尚需在一次性 Windows 测试账户用标准安装包验收；源码中未发现本次启动、应用启动、卸载配置或升级逻辑新增对该目录的清理。

旧用户样本、权限拒绝样本及实际升级恢复风险仍为“待维护者确认”。目前源码证据支持保持轻量文档指引，不支持重加旧写入引擎。
