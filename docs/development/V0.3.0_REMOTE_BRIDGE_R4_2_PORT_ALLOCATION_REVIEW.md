## 行为与探测顺序

| 函数 | 保留的行为 |
| --- | --- |
| `derived_port` | SHA-256 输入仍为指纹、换行和十进制轮次。lane 0 和 1 读取各自的两个小端字节，范围仍为 20000–60000。每 lane 仍为 24 个候选，顺序为第 0–23 轮。 |
| `first_available_port` | 按原顺序调用 `FnMut` 并跳过排除的端口。首次可用立即返回。闭包错误直接传播，候选耗尽继续返回 `portAllocationFailed`。 |
| `resolve_port_pair` | VS Code 期望端口优先，原 HTTP/Mixed 与 SOCKS 分支由调用层继续负责。有期望端口但被占用时直接进入普通代理候选。无期望端口且启用默认值时先试本机代理端口。CC 在启用默认值时先试 15721，跳过已选普通代理端口，再走自己的候选。 |

- `port_allocation_preserves_preference_and_probe_order` 覆盖六种组合。期望端口和第一个普通候选都被占用时，实际探测顺序为 `7897 → 41616 → 28163 → 15721`。CC 默认端口和第一个 CC 候选被占用时，顺序为 `10809 → 15721 → 28527 → 20824`。两通道同时优先 15721 时只探测一次该端口，随后探测 CC 候选 28527。
- `port_allocation_exhausts_exactly_one_lane_at_a_time` 对照两组固定的 24 候选序列。普通代理候选耗尽时共调用 24 次且不会进入 CC。普通代理首选 7897 成功、CC 候选耗尽时共调用 25 次。两种情况均返回原错误码。
- `port_allocation_propagates_probe_errors_without_trying_more_ports` 分别在期望端口、普通回退和 CC 回退返回合成错误，闭包依次只被调用 1、2、3 次，原错误立即返回。原用例继续验证同一指纹的稳定性及两条 lane 的独立性。

新模块仅通过调用方提供的闭包获取可用性。调用层的 `ssh::remote` 请求和 `portInUse` 处理逐字节相同。测试用闭包记录每一次调用，未发起远程探测。该改动不引入跨请求缓存，已建立隧道的分配及生命周期保持原样。
