## 实现

- `skills.rs` 从当前连接同时取得目标 ID 与既有 SSH 配置指纹。手动操作与后台重试用这对值建立绑定。运行时投影状态按指纹归属，同一别名下重新连接到另一主机时重新检查其状态。
- `ssh.rs` 在绑定建立、每个 SSH 阶段和每次 SCP 启动前复核 OpenSSH 生效配置。对配置型目标保留原别名与 SSH 选项，同时用绑定的 `HostName`、`User`、`Port` 构造进程参数。只使用绑定时的指纹查询缓存凭据。
- `apply` 和 `cleanup` 从已确认 `prepared: true` 的同一批次获取目标和清单。变更后拒绝启动后续操作。`status`、独立移除以及本地存储失败后的回滚也走绑定校验。
- 保留现有主机密钥检查、固定 Linux 探针及脚本内平台检查。Linux 脚本、请求字段、命令载荷和 SCP 远端路径沿用 M1 实现。
- `scripts/test-remote-bridge.mjs` 保留 Skills 状态与移除契约，断言更新为校验绑定参数及同一暂存批次。

## 验证

双目标夹具使用本机 `ssh -G` 指向两个无网络连接的示例目标。它在同一 SSH 别名下改变主机、用户及端口，
检验旧指纹拒绝新配置、旧命令选项仍锁定原端点、未能核对绑定时 apply 和 cleanup 返回 `sshConfigChanged`。
恢复原配置后，原绑定重新通过。新目标须匹配新连接的独立指纹；旧连接的后台重试不能凭当前别名对新目标建立绑定。

Rust 格式与 `cargo clippy --all-targets --locked -- -D warnings` 通过。允许本机回环后，Rust 库测试
313 通过、0 失败、3 忽略，包含双目标夹具、运行时状态隔离、Linux 载荷 26 项字节一致性和平台拒绝。
默认沙箱阻止回环连接，导致 32 个现有 Rust 测试失败。相同用例在允许回环后通过。
三项定向 Node 契约检查通过，覆盖 Skills 脚本行结尾、同步状态和暂存流程。

## 剩余边界

**真实 Linux SSH/SCP 验收为 PENDING。** 当前没有明确授权的 Linux 测试主机。断连或目标变化后，
原主机可能留有暂存文件。若无法确认原绑定，停止 cleanup 并保留原报错；重连后通过既有 `status`
及投影环节核对或恢复。`HostName`、`User`、`Port` 在进程参数内固定，其他 OpenSSH 配置和主机信任仍由
OpenSSH 按启动时配置处理。多个独立 SSH/SCP 进程之间没有服务端事务。
