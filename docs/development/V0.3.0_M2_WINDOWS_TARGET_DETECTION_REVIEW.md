# RouteSpan v0.3.0dev — M2 Windows Target Detection Review

基于 M1.1 `0a16d6338960addcdd22e8b15aaf604a137ac922`。原方案见
[M2 Windows Target Detection 设计](V0.3.0_M2_WINDOWS_TARGET_DETECTION_DESIGN.md)。

## 接口和范围

- 新增显式 Tauri 命令 `remote_bridge_probe_target_os`，输入已有 SSH 目标的 `targetId`。结果为 `confirmed` + `shell`（`cmd` 或 `powerShell`），或 `unknown` + `reason`。SSH 传输错误仍按既有错误码返回。
- `target_os/windows.rs` 先尝试固定 PowerShell 语法，再在退出码 0 或 1 且 stdout 为空时尝试 cmd 模板。cmd 通过固定路径启动 Windows PowerShell 5.1。每个候选使用独立的 128 位随机值。只有退出 0、空 stderr 以及唯一一条完整且匹配的 ASCII 回执才能确认。
- `ssh.rs` 复用目标绑定、已有验证过的 SSH 凭据和严格主机密钥校验。两个候选和配置复核共享 25 秒预算，每次连接最多 8 秒。stdout、stderr 各限 4 KiB，超时或超限停止子进程，关闭 Windows Job Object 并等待两条读取线程退出。确认结果返回前复核配置指纹。
- 探测禁用 SSH 转发、主机密钥更新和自动向 Agent 加载密钥。对启用 `CheckHostIP`、自定义 `KnownHostsCommand`、`ProxyJump` 或 `ProxyCommand` 的目标返回 `sshConfigUnsupported`，避免为了诊断更改其校验策略，或启动不继承本探测只读选项的辅助进程。既有普通 SSH 路径仍处理这些设置。[OpenSSH 客户端选项](https://man.openbsd.org/ssh_config)
- 探测入口仅供诊断。现有页面和桥接流程没有自动触发此命令，原 Linux 平台写入门禁继续独立执行。

## 验证范围

本地 shell 夹具覆盖 `cmd.exe`、Windows PowerShell 5.1、PowerShell 7 和 Git Bash。协议用例覆盖
重放或随机值不符、重复与截断回执、错候选、BOM、NUL、stderr 和非零退出。进程夹具覆盖两条输出流
溢出、超时和回收。现有 Linux 安全断言与 26 项命令及载荷摘要纳入同一次回归。

Rust fmt 与 `cargo clippy --all-targets --locked -- -D warnings` 通过。Rust 库测试 320 通过、0 失败、
3 忽略，包含新增的 7 项探测回归。Node 文档契约 13 项通过。Linux 脚本、Linux 载荷摘要、Relay 鉴权、
依赖锁文件与生产版本对比初始基线无差异。

## 实机验收与限制

**Windows OpenSSH 和 Linux SSH/SCP 实机验收均为 PENDING。** Windows 仍需用实际 sshd 验证默认 cmd、
PowerShell 5.1/7、认证及 OpenSSH 命令转义。初版 cmd 使用 `C:\Windows` 下的系统程序，非默认安装位置
或禁用该程序的策略可能返回 `unknown`。远端用户配置的 shell 启动钩子可产生自己的输出与副作用，
OpenSSH 用户配置也可在解析时执行 `Match exec`。严格回执仅代表本次命令环境，无法证明物理主机的操作系统。
诊断运行上限由统一超时控制，当前没有独立的取消命令。
