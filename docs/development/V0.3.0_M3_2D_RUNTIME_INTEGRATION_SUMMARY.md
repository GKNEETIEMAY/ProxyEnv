## 状态和资源所有权

`runtime.rs` 管理未准备、准备中、等待授权、等待资源就绪、离线可用、关闭中、已关闭和异常关闭。任务身份限制所有状态转换与资源交接，关闭结果缓存到原任务。旧任务和其他运行时的身份无法操作现有资源。

`runtime/local.rs` 从 `WindowsBridgePlan` 和主机身份检查建立租约作用域，使用 `PolicyLifecycle` 和 `PolicyStorage` 确认签名授权及持久历史，再持有 `FrozenResources` 和 `OwnedProcess`。启动受控子进程、校验配置和恢复线程前后重新检查授权。合成时钟到期即报告不可用，下一次轮询关闭资源。迟到的签名或历史异常不会延长有效期限。

进程和文件保留并共用 `close_until(deadline)` 绝对截止，不引入无限等待、固定长延时或非自有进程操作。常规关闭与 `Drop` 兜底的单次 Job 等待上限为 5 秒；`End::ApplicationExit` 对齐 [R4.6-F6 应用退出协调](V0.3.0_REMOTE_BRIDGE_R4_6F6_APPLICATION_EXIT_REVIEW.md) 的两个退出边界——**正常退出协调 3 秒**（`COORDINATED_EXIT_BUDGET`，将应用退出截止钳制在 3 秒上限内并保留调用方已消耗后的剩余时间，协调完成后再次触发兜底直接返回缓存结果）与**最终退出兜底 200 毫秒**（`EXIT_FALLBACK_BUDGET`），两者均通过本机合成 Job 子进程与 NTFS 冻结文件实测。`OwnedProcess::closed`、`FrozenResources::cleanup_deadline` 与 `activate` 回滚单次截止共享保证根进程等待、Job 排空、文件按句柄删除与所有者 `Drop` 均不会嵌套重获 3 秒或 5 秒完整预算。

关闭路径明确区分五类结果，且当前 `TerminateJobObject` + `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` 属于强制终止，不描述为优雅退出：

- **正常退出**。关闭前自有子进程已自行退出且 Job 活动进程归零（`CloseReport { forced: false, process_exited: true, job_empty: true, termination_error: None, timed_out: false }`），无需调用 `TerminateJobObject`，冻结文件与目录完整移除（`Completion::Complete`）。
- **强制回收**。子进程或 Job 仍活动时执行 `TerminateJobObject(job, 1)` 强制终止（`forced: true`），在剩余预算内确认根进程退出且 Job 清空后移除冻结文件与目录（`Completion::Complete`）。
- **超期**。根进程等待、Job 排空或文件删除达到/越过绝对截止时报告 `Completion::TimedOut`；未消解的自有文件与自有目录均以 `TimedOut` 保留创建时验证的 `FileId`。
- **部分清理**。未超期且至少一项自有资源已完成停止或移除，但仍有残余异常（如外部文件驻留导致自有目录 `.` 保留待清理身份，或根进程已退出而 Job 排空/终止返回错误），报告 `Completion::Partial`。
- **失败**。未超期但未能回收任何自有资源且存在未完成项（如三份自有冻结文件均被禁止删除共享的句柄占用导致回滚无进展，或非超期的进程终止失败），报告 `Completion::Failed`；进程未排空且非超期时，挂起文件记录非超期错误而非伪造 `TimedOut`。

文件回收保留 D3 的 NTFS 按句柄扩展删除、历史快照扩展原子替换、当前用户 SID/DACL（`O:{sid}D:P(A;;FA;;;{sid})`）、祖先句柄固定及 `FILE_SHARE_READ` / `FILE_SHARE_MODE(0)` 共享限制。`FrozenResources::close` 先核对剩余预算再释放只读锚定句柄；资源退役时若自有文件尚未删空导致目录仍驻留磁盘，`pending` 同时记录未删自有文件与自有目录 `.` 的 `FileId`，而预先存在的外部目录（`AlreadyExists`）与目录内外部文件不计入自有清理目标。同步 Win32 调用的中断和实际宿主退出调度仍为 PENDING。

其余实现变更集中在 `safety/mod.rs` 的作用域复用、`policy/lifecycle.rs` 的时效查询、`owned_process.rs` 与 `frozen_resources.rs` 的期限传递与退役统计、`local_files.rs` 的按句柄删除以及 `policy_storage.rs` 的原子发布。测试变更涉及 `tests/mod.rs`、`tests/policy_lifecycle.rs`、`tests/policy_storage.rs`、`tests/process.rs`、`tests/runtime_integration.rs` 和 `tests/runtime_regression.rs`。三份阶段 Review 与开发索引随汇总交付。

## 接口边界核对

现有五项离线与计划组件职责单一、契约闭合，本轮不修改 `WindowsBridgePlan`、`PreparedForward`、`Verification` 与 `PolicyLifecycle` 代码，不重复实现已有验证逻辑，也不新增第二套全局 `Store`：

| 组件 | 当前职责与数据契约 | 未来 M3.2-E 生产接线接口需求（本轮不实现实际网络接线） |
| --- | --- | --- |
| `WindowsBridgePlan` | 依据受审主机策略（`REVIEWED_TEST_HOSTS` 现为空）、`BoundTarget` 指纹、SSH 安全选项白名单、`WindowsTargetProbe::Confirmed`、`VerifiedHostIdentity`、环回上游代理修订和 `GatewayPorts::No` 建立计划；`forward_args` 复核上下文后仅输出单一 `-R 127.0.0.1:<remote>:127.0.0.1:<ingress>` 对。 | 受控无转发认证探针签发私有 `VerifiedHostIdentity`，以及经维护者独立审批的主机策略与 `PolicyIssuer` 注入入口。 |
| `PreparedForward` | 组合 `WindowsBridgePlan`、`LeaseScope`、单次 `VerifiedPolicy`、`FrozenProfile` 与固定 7 项 SSH 参数；`check_launch` 与 `check_current` 校验策略时效、三份冻结文件原始字节、固定参数和单调状态序号。 | 从活动 `LocalRuntime` 导出已固定的 7 项启动参数、冻结文件字节快照与当前 `VerifiedPolicy` 视图，直接复用 `check_launch` / `check_current` 而不复制校验实现。 |
| `Verification<R>` | 单次前置流量门禁（`Listening -> AwaitingReceipt -> Verified \| Closed`），独占待验证资源 `R`；在 `min(15s, policy.deadline)` 内核验 `<= 4096` 字节且仅绑定 `127.0.0.1` 的 `ListenerReport` 与带 `EOF` 的 `ROUTESPAN-FORWARD/1\0` 单次回执，`finish` 复核无误后才移交 `R`，任何异常立即丢弃 `R`。 | 以受控子进程管道/监听探针喂入实机监听报告与隧道回执，仅在 `Verification::finish` 放行后向既有本机 Relay 开放上游转发。 |
| `PolicyLifecycle` | 围绕固定 `PolicyIssuer` 与 `LeaseScope` 管理显式登记（`Existing` / `IndependentlyApproved`）、随机挑战新鲜度证明、CAS 持久化（`PolicyHistory` / `PolicyStorage`）、撤销不可逆性及双时钟锚点防延展截止。 | 通道外独立权威 `StatusSource` 客户端（严格受 `StatusRequest.deadline` 约束）及受管本机应用数据目录下的持久化根目录定位。 |
| `LocalRuntime` | 单次任务的 Windows 本机资源协调器，串联 `prepare -> refresh -> activate -> available/poll -> stop`，在单任务令牌下管理 `FrozenResources` 与 `OwnedProcess` 的激活回滚、策略轮询及共享截止关闭。 | 将活动句柄纳入现有唯一 `remote_bridge::Store`（`StateStore`），由通道外硬截止定时器、断开/代次切换、R4.6-F6 的 3 秒 `coordinate_shutdown` 与 200 毫秒 `shutdown` 兜底显式传入共享 `Instant` 调用 `stop`，并在关闭进程前先切断入口流量与在途管道 I/O。 |
