## E1 桌面产品安全模型

建议继续以用户明确授权的单一设备会话为产品单位。RouteSpan 在本机保留代理与 AI 配置，将授权限定在当前设备、账号、当前主机密钥、当前 SSH 配置、会话代次和明确的能力范围。远端使用所需能力，代理和 AI 凭据留在本机。

| 范围 | 决策建议 |
| --- | --- |
| A 桌面必需 | 保留标准 OpenSSH 的有效信任与撤销约束。每条新 SSH 连接独立确认主机身份，连接用途、目标、代次和冻结证据一致。用户对设备与能力明确授权，同时核验实际服务端转发权限与监听策略。先确认经批准的 `GatewayPorts=no` 证据，再核查实际 IPv4/IPv6 监听范围与一次性回执。验证前网关关闭。明确的断开、撤销、到期或证据失效停止访问，回收本次拥有的连接、进程与文件。 |
| B 受管部署 | 独立权威状态服务、中心化登记与恢复审批、部署隔离及企业密钥轮换可归入受管接入。当前受管计划依赖独立审核的服务器策略、精确部署/修订、固定签发公钥、签名租约和新鲜状态、持久历史和维护期间先撤销后变更。桌面替代方案需提供下表中的等效保障，再由维护者另行审批。 |
| C 延后扩展 | 托管进程的代理环境、桥接前后端状态联动、AI 路由、热切换和多应用使用按 M3.3、M3.4、M4 分别开发。批量设备配置、企业自动轮换与管理后台可继续延后。 |

| 安全保证 | 桌面方案准备与当前准入结论 |
| --- | --- |
| 实际服务端权限和监听范围 | 可评审由目标所有者通过独立、可信的管理通道提供范围明确且有期限的有效服务端策略证据，同时在独立验证的 SSH 会话中核对实际权限、地址族和范围。用户同意仅授予本机意图。证据缺失、变更未获撤销保障、端口或范围异常均继续阻断。 |
| 原主机信任完整保留 | 冻结过程需证明保留适用的全局和用户 known_hosts、CA、撤销/KRL、别名匹配、算法和组织规则。无法证明等价时拒绝使用 `GlobalKnownHostsFile none` 的路径。握手观察必须由受控执行器完成，未经验证的扫描或远端自报不具备签发资格。当前没有生产签发入口。 |
| 授权新鲜度、撤销和硬截止 | 桌面形态仍需会话外可信、可验证且能判定新鲜度的状态来源，以及可关闭已有能力的独立本机截止调度。具体来源、登记与恢复规则、谁可撤销及服务端变更前如何确认旧会话关闭均待维护者审批。DPAPI 和 ACL 保护本机历史，整份数据回滚仍需外部新鲜度与单调序号的证据。面向普通用户的点击确认无法建立这些保证。 |
| 资源和访问隔离 | 生产路径需落在受保护的当前用户存储根，复核文件和目录身份、共享及实际有效权限。进程先进入自有 Job 再运行，真实管道、Job 排空、未完成清理的所有权与恢复纳入宿主验收。冻结材料、用户凭据、CC Switch 数据与密钥保持在本机信任边界内。 |

本轮保留 `REVIEWED_TEST_HOSTS` 为空及已有全部拒绝条件。桌面等效方案目前是审批事项。生产准入还需要证据链、独立失效与关闭控制、本机受保护路径和宿主回收的验证。

## E2 离线接线与所有权

| 现有组件 | 本轮接线边界 |
| --- | --- |
| `BoundTarget` / `VerifiedHostIdentity` / `WindowsBridgePlan` | 继续使用计划的目标和代次校验。前置和完成阶段均复核有效目标、SSH 配置指纹、账号、主机密钥、当前代理修订、端口及审查窗口。 |
| `PolicyLifecycle` / `PolicyStorage` | 当前决定重新通过持久历史、双时钟与失效状态检查后才返回授权视图和当次样本。缺失、撤销、到期或读取异常都拒绝验证，并由现有原因触发离线关闭。旧的单次签名验证继续供原夹具使用。 |
| `FrozenResources` / `FrozenProfile` / `PreparedForward` | 从当前所有者持有的冻结文件核验目录、文件身份与原始字节，再组装既有 `PreparedForward`，核对计算的七项启动参数与交付参数。完成回执时再次获取当前材料，并复用原有 `check_current` 和 `check_launch`。 |
| `Verification<()>` / `LocalRuntime` | 离线验证值携带不可混用的 `Task`，复用有界的监听报告、一次性随机回执及绝对截止。前置和完成均要求当前任务已拥有离线资源。验证结果仅为 `BridgeResult<()>`。Job 和文件句柄一直由 `LocalRuntime` 持有。旧任务被拒绝时不会关闭新任务。 |
| 现有状态投影 | `Available` 只表示本机测试进程和文件已受控。内部证明不投影到 IPC、Report、Tray 或 `Connected`，也没有真实 SSH 任务绑定到此接口。Linux 仍使用现有连接、重连和 Relay 生命周期。 |

关闭沿用 D 的单次绝对截止。常规资源关闭上限 5 秒，应用正常退出协调上限 3 秒，最终兜底 200 毫秒。等待租约、验证或文件读写不会为已有关闭链补满预算。仅当根进程确认结束且 Job 排空时才按持有句柄和身份清理冻结资源。否则 `retire_unclosed` 放弃删除，由原关闭任务的 `Shutdown.pending` 保存文件和目录的 `FileId` 及失败原因。退役对象释放句柄后，记录仅提供身份复核证据，持久的路径和内容防护仍受生产存储、权限和宿主设计门禁约束。未来接线由原会话清理所有者处理待清理记录，先证明 Job 停止，再重验目录及文件身份并回收。终止请求与进程、管道、文件均回收分别记录。

在接入真实流量前，仍需绑定受控 SSH 进程身份、实际 OpenSSH 启动参数和独立握手，确保监听和回执确实来自当前连接。实机监听证据、生产入口及硬截止调度由后续阶段单独验收。M3.2-E 未接入 SSH 或 Relay。

E2 提交前运行 `cargo test --manifest-path src-tauri/Cargo.toml --lib --locked windows_bridge::safety`，既有 Windows 离线安全套件 45 通过、2 个既有夹具入口 ignored。复审将验证入口收敛为原有的带校验构造函数，合并 E3 夹具后的同一过滤回归为 48 通过、2 个既有 ignored。证据在 `artifacts/v0.3.0/M3.2-E/`。

## E3 本机闭环

| 项目 | 新旧验证证据 |
| --- | --- |
| E01 取消准备 | 复用 `runtime_boundaries_cancel_preparation_and_reject_stale_actions`，验证取消前后的阶段和资源无副作用。 |
| E02 目标身份变化 | 复用 `host_identity_is_bound_to_the_exact_effective_config_and_generation`。新增 `desktop_verification_rejects_other_tasks_and_host_key_changes`，验证取得回执后主机密钥变化仍拒绝交付，并回收当前合成任务。 |
| E03 缺少授权 | 复用 `runtime_components_fail_closed_when_authority_history_or_preparation_fails`。新增 `desktop_verification_requires_authorized_owned_resources_and_preserves_the_owner`，在准备后、授权前验证拒绝且无冻结文件。 |
| E04 无法确认安全配置 | 复用固定 SSH 参数、权限、额外转发和握手证据的原断言。新增 `desktop_verification_rechecks_history_deadlines_and_arguments_before_completion`，验证完成时参数不符或回执缺失均拒绝并回收。 |
| E05 正常准备 | 新用例在合成授权、真实本机 Job 和冻结文件准备后提交两段有效模拟证明。验证成功后原任务仍持有资源。 |
| E06 单一任务所有权 | 复用 `lifecycle_ownership_rejects_resources_before_authorization` 和 `lifecycle_ownership_ignores_obsolete_and_foreign_tasks`。新用例确认回执交付过程中不存在 Job 或冻结文件的所有权转移。 |
| E07 主动断开 | 新用例观察原 Job 子进程退出、无待清理报告、冻结目录删除。原 `runtime_components_close_real_local_resources_on_policy_events` 继续覆盖主动断开、到期与撤销。 |
| E08 异常及超期 | 原 `runtime_boundaries_report_application_exit_and_exhausted_budget` 验证现有退出时间边界。新用例验证证明或租约刚到期、回执后历史损坏、参数变化和不完整回执，均拒绝交付并关闭合成资源。 |
| E09 新旧任务隔离 | 旧任务即使已取得有效模拟回执，也不能在相同计划的新任务上完成。新任务原有资源继续有效。 |
| E10 Linux 行为 | 复用 `linux_wire_bytes_match_pre_adapter_baseline`、SSH/Relay 回归和基线 Linux 扩展任务。26 项冻结载荷及清单字节不变。 |

新增验证仅使用测试密钥、合成授权、本机自有测试进程和隔离目录。一次性证明值仅拥有本地证据，无法打开上游。生产进程需要在报告、回执、超时或目标变化任一步失败时由当前所有者立即封闭入口并触发关闭，且不得依赖后续交付调用。此处已验证的是离线交付边界。
