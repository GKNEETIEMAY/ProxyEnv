## 缺陷及最小修复范围

- **退出二次阻塞及漏清理。** `shutdown` 的 `try_lock` 争用时跳过清理，随后 `ssh_auth::shutdown` 又经 `cancel_interactive_connect` 阻塞获取 Store。第一次跳过的资源清理不会在这次重拿锁时补做。建议在根模块与认证模块明确一个有界关停协调入口，避免认证关闭隐式重拿 Store，同时明确争用时由谁完成资源移交和回收。正常关闭应在原守卫发布前建立一致终态，沿用视图派生路径。覆盖有争用、无争用和重复关闭，并用假资源校验具体回收顺序。[桥接关闭](../../src-tauri/src/features/remote_bridge/mod.rs#L2527) · [认证关闭](../../src-tauri/src/features/remote_bridge/ssh/ssh_auth.rs#L1089) · [重拿 Store](../../src-tauri/src/features/remote_bridge/mod.rs#L2247)
- **已停止时仍可接纳工作。** 建议在通用操作接纳边界落实停止条件，并让主 monitor、Skills 循环和已经派发的任务在安全检查点服从同一关停状态。保留正常的更新租约计数与重连代次规则。回归应验证关闭后新工作被拒绝，旧工作不会发布成功。[Gate](../../src-tauri/src/desktop/updates.rs#L65) · [恢复提交](../../src-tauri/src/features/remote_bridge/runtime/reconnect.rs#L120)
- **旧 Profile 回执越过代次。** 在现有同步路径中，将忙位绑定到认领它的工作身份。统一验证代次、目标和工作身份后才发布状态或释放忙位，旧成功和失败回执均须覆盖。远端副作用单独审查，当前证据只认可本机状态的最小修复。[Profile 认领](../../src-tauri/src/features/remote_bridge/mod.rs#L1179) · [Profile 结束](../../src-tauri/src/features/remote_bridge/mod.rs#L747)
