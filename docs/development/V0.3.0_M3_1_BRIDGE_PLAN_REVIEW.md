## 模型与接口

`WindowsBridgePlan::build` 是后端内部纯函数。它从 `BoundTarget` 读取账号、主机与 SSH 端口，并用原有
指纹算法核对 OpenSSH 生效配置。输入还包含同一认证目标的 M2 `WindowsTargetProbe`、主机密钥身份、
当前连接代次和 `ActiveProxyContext`。`WindowsBridgePlan::forward_args` 在重新核对当前输入及有效期后
返回两个固定参数 `-R` 和 `127.0.0.1:<已批准远端端口>:127.0.0.1:<本机入口端口>`。
它接收整数端口和结构化地址，最终参数不包含账号、主机名、任意命令或额外选项。

`ManagedHostPolicy` 将独立审查记录编号与有效 SSH 主机、账号、端口、已验证主机公钥 SHA-256、
`GatewayPorts` 值、允许的远端端口范围及 UTC 生效区间绑定。首版仅接受 `GatewayPorts=no`。
只从仓库维护的私有清单按唯一编号查找记录。没有授权实机，清单为空。测试记录仅作为内部夹具使用，
没有文件导入、远端策略输入、IPC 或 UI。传入记录编号或 OpenSSH 客户端配置行均不能创建有效的审查记录。
任何未来入册记录都应证明批准的端点和账号在有效期内的适用 `Match` 条件下均满足 `GatewayPorts=no`。
[M3 设计](V0.3.0_M3_WINDOWS_NETWORK_BRIDGE_DESIGN.md) · [OpenSSH GatewayPorts](https://man.openbsd.org/sshd_config#GatewayPorts)

`VerifiedHostIdentity` 的字段封闭，读取时绑定 `BoundTarget` 指纹和连接代次。本阶段仅有测试构造器。
现有 SSH 主机密钥校验仍由 OpenSSH 执行，现有确认提示或 M2 回执无法签发该类型。后续若接入，需要在认证传输层
取得结构化的实际握手对端密钥，并从同一个绑定、同一个代次采集平台证据。此验证没有从远端命令输出提取身份。
[M2 验收](V0.3.0_M2_WINDOWS_TARGET_DETECTION_REVIEW.md) · [M1.1 验收](V0.3.0_M1_1_SKILLS_TARGET_REVIEW.md)

## 安全不变量与兼容范围

- 策略缺失、编号重复、尚未生效、到期、计划生成后的时钟回拨或记录与主机密钥、账号、SSH 端点不符均拒绝。
  `clientspecified`、`yes` 和 `Unknown` 也拒绝。
- 两端参数固定为 IPv4 `127.0.0.1`，远端须在已审查的非特权端口范围内。本机入口要求合法非特权端口，拒绝复用同一 IPv4 上游地址。
  上游须仍在监听、为数字 loopback，且为 HTTP、SOCKS5 或 Mixed。
- 复用 M2 的 `ProxyJump`、`ProxyCommand`、`KnownHostsCommand`、`CheckHostIP` 拒绝规则。已有本地、远端、动态及 stdio 转发和启用的 TUN 也不符合计划。
  M2 `Unknown` 及缺失已验证主机身份均拒绝。
- 生成参数之前复核目标指纹、账号与端点、主机密钥、Shell、代次、本机代理修订及实际端点。旧目标和已切换的本机代理无法复用计划。
- 计划只产生一对参数。未来启动器还须证明 OpenSSH 将使用同一份受控配置和主机信任设置，避免进程启动时读入额外转发。
