## A 环境模型

`ProcessEnvironment` 接受调用者提供的进程环境副本与既有 `ProxyEndpoint`。托管进程使用 Windows 桥接计划中的远端回环监听 `127.0.0.1:<端口>` 和已确认的上游协议。空端口、非计划回环地址、嵌入凭据的地址和 `Unknown` 拒绝生成环境。

| 端点协议 | HTTP 客户端环境 | SOCKS5 客户端环境 |
| --- | --- | --- |
| HTTP | `HTTP_PROXY`、`HTTPS_PROXY` 指向 `http://127.0.0.1:<端口>` | 无 `ALL_PROXY` |
| SOCKS5 | 无 `HTTP_PROXY` 或 `HTTPS_PROXY` | `ALL_PROXY=socks5h://127.0.0.1:<端口>` |
| Mixed | HTTP 两项均指向同一端口 | `ALL_PROXY` 使用相同端口的 `socks5h://` |
| Unknown / 非法端点 | 拒绝 | 拒绝 |

Windows 序号忽略大小写规则用于识别和排序变量名。所有旧的托管代理键在副本中替换。无关变量及空值保留。遗留 `NO_PROXY` 合并非空条目、保留首项原拼写，补充 `localhost`、`127.0.0.1`、`::1`。独立的 `*` 保留全绕过语义。结果以双 NUL 结尾的 UTF-16 环境块传给指定进程。支持环境变量的客户端可以继承该配置，代理协议和网络出口后续单独验证。[环境模型](../../src-tauri/src/features/remote_bridge/target_os/windows/process_environment.rs)

## B 进程所有权和结果

`LocalRuntime` 继续持有当前 `Task`、`PolicyLifecycle`、`PolicyStorage`、冻结文件与唯一的 `OwnedProcess`。本轮夹具把受控本机进程放在该所有权位置。启动沿用 `activate` 验证目标、主机身份、连接代次、代理快照及授权，创建冻结资源后把子进程置于自有 Job，再恢复线程。重复启动和旧任务直接拒绝。运行与回执交付时复核当前授权和进程状态。非法回执、目标变化、到期及不可确认的进程状态结束当前尝试。

`CreateProcessW` 接受明确提供的 Windows 本机工作目录及子进程环境块。目录须为存在的本地磁盘目录，并经过规范化。工作目录由调用者提供，路径不出现在状态或日志中。本机 C 夹具验证空格、非 ASCII 和目录大小写差异；无效目录在创建子进程前返回启动失败。CMD 与 PowerShell 使用固定夹具命令、禁用 AutoRun 或用户 Profile，并通过平台类型选择。PowerShell 5.1 和 7 的区分来自实际子进程版本输出。

| 内部状态 | 含义 |
| --- | --- |
| `Unprepared` | 当前任务尚未启动托管进程 |
| `AwaitingReceipt` | 子进程已获 Job 所有权并运行，正在等待当次随机回执 |
| `Prepared` | 当次回执通过并完成任务、连接、授权及自有进程复核 |
| `Closed(Shutdown)` | 关闭原因包含启动失败、取消、授权失效、进程退出等。清理结果独立报告完整、部分、超期或失败 |

关闭复用 M3.2-D 的 5 秒常规资源上限、3 秒应用协调上限、200 毫秒最终兜底及共享绝对截止。冻结文件只在确认根进程退出及 Job 排空后移除。无法确认时继续使用原任务的 `Shutdown.pending` 和文件身份保留待清理证据。现阶段的环境就绪为离线内部结果，报告和前端 IPC 的真实连接状态仍走原入口。[本机启动与回执](../../src-tauri/src/features/remote_bridge/target_os/windows/bridge/safety/runtime/local/managed.rs) · [资源所有者](../../src-tauri/src/features/remote_bridge/target_os/windows/bridge/safety/runtime/local.rs) · [Job 与 CreateProcessW](../../src-tauri/src/features/remote_bridge/target_os/windows/bridge/safety/owned_process.rs)

## C 实际继承和隔离

本机探针从隔离父进程取得合成代理配置。每个受控 Shell 报告实际收到的代理变量和工作目录证据，再等待父进程确认。CMD 在同一 Job 内启动固定测试子进程，由该进程读回实际环境、返回本次回执，并通过相对路径读取仅存在于指定目录的合成见证文件。PowerShell 的固定探针直接报告进程版本和当前目录。混合协议用例额外启动独立观察进程，校验其继承父进程的原配置，同时确认旧代次的已收集回执拒绝提交。每次关闭验证根进程停止、Job 排空、冻结目录和本机见证目录回收。

新增测试分为 A 的 5 项变量模型检查、B 的 3 项任务所有权及关闭检查、C 的 3 项实际 Shell 检查。A 覆盖三种协议、未知及畸形端点、无关变量保留、大小写冲突、空绕过项、`NO_PROXY` 合并及独立副本。B 覆盖未授权和已取消请求、重复启动与关闭、其他任务的迟到结果、启动失败、过期、提前退出和无效目录。C 按实际 Shell 运行 HTTP、SOCKS5、Mixed 三种组合，明确验证代理变量缺省时回执仍完整。[生命周期及继承夹具](../../src-tauri/src/features/remote_bridge/target_os/windows/bridge/safety/tests/managed_environment.rs) · [固定 Shell 夹具](../../src-tauri/src/features/remote_bridge/target_os/windows/bridge/safety/owned_process/shell_fixture.rs)

CMD 初版把含正斜杠的可执行文件路径放进 `argv[0]`，CMD 将其中的斜杠误解为选项，导致 `/d` 未抑制本机 AutoRun。诊断日志捕获到一次 `chcp` 调用失败及后续参数解析失败。夹具修正为 Windows 原生分隔符，并在调用前拒绝 CMD 路径中的正斜杠。最终由同一 Job 内的固定测试子进程读取继承环境并核验 Unicode 工作目录。首轮全量失败及后续诊断日志保留在 `artifacts/v0.3.0/M3.3/`。RustSec 首次请求遇到 GitHub TLS 握手提前结束，复跑成功刷新公告及 crates.io 索引。

最终 C 回归确认实际 CMD、Windows PowerShell **5.1.26100.9818**、PowerShell **7.6.9** 各自通过 HTTP、SOCKS5、Mixed 三种组合。额外三轮复验共 9/9 个 Rust 用例通过。验证退出后先释放测试倚赖的管道与观察句柄，再显式核对见证文件和工作目录的删除结果。早期失败留下的自有临时目录已按实际归属清理。
