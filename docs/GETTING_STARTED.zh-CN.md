# RouteSpan 快速开始

[English](GETTING_STARTED.md) · 简体中文

本指南说明 RouteSpan v0.2.1 稳定版界面的用法。请安装
[官方 v0.2.1 发行包](https://github.com/GKNEETIEMAY/ProxyEnv/releases/tag/v0.2.1)。
已有 RouteSpan 和旧品牌 ProxyEnv NSIS 用户可使用关于 → 检查更新；v0.1.4 已公开发布，为历史版本。
预览包不是已签名的自动更新版本。

## 安装前

- 本机为 Windows 10/11 x64。普通用户不需要安装 Node.js 或 Rust。
- 需要 WebView2；缺少时安装程序可能需要联网下载。
- 桥接网络需要你自己的本机代理客户端；AI 路由需要 CC Switch。
- 远程访问需要 Windows OpenSSH 和可访问的非 root Linux 账户。服务器需要 `ss`、
  `flock` 和 coreutils。托管工具的 JSON 操作支持 Python 2.7 或 Python 3，仍需通过运行时和文件安全检查。
- VS Code 集成需要安装 VS Code 和 Remote - SSH；MobaXterm 为可选项。

手动安装前，退出旧应用和托盘实例。应用保留安装身份，因此新安装包可能替换旧安装，
而不是创建另一份独立应用。升级前备份重要设置。未采用 Authenticode 的包可能出现 Unknown Publisher
或 SmartScreen 提示：检查来源和校验值，不要全局关闭安全防护。详见[发行安全](release-security.zh-CN.md)。

## 首次启动

可在设置中选择语言和主题。本机环境与远程桥接是两个主工作区；退出设置时返回打开设置前的工作区。
标题栏诊断报告是全局入口。关闭窗口是否隐藏到托盘，取决于已保存的偏好设置。

## 本机环境

1. 启动你正在使用的本机代理客户端。
2. 确认检测到的监听端点，选择一个活动代理。
3. 分别查看系统代理、TUN 和环境变量状态，不要将它们视为同一层。
4. 按需应用代理环境变量，通过明确操作清除或恢复。已经运行的应用不会自动继承后续修改。
5. 打开应用助手，诊断选定应用，或以代理/直连环境启动新进程。它不会自动重配任意应用。

自动刷新不会在原代理不可用时悄悄切换到其它端点。应重新选择可用代理，而不是依赖旧环境变量。

## 首次远程连接

1. 选择导入的目标，或添加 SSH 连接。默认 SSH 端口为 22。
2. 选择**桥接本机网络**、**CC Switch AI 路由**，也可同时开启。
3. 使用 AI 前，先在 **CC Switch → 设置 → 路由 → 本地路由 → 路由总开关 →
   开启 Claude/Codex 路由**中启用对应能力。仅检测到监听服务，不代表两个路由均可使用。
4. 建立连接，复用密钥/Agent，或回应真实 OpenSSH 密码/Keyboard Interactive（KBI）提示。
   首次见到主机指纹时，应先核实再确认信任；已知密钥变化会导致失败。
5. 核心转发验证完成后进入已连接概述。可选的工具和环境准备独立继续，不阻塞核心连接状态。

在终端检查 SSH 时使用 `ssh -p 22 user@host`，不要写成 `ssh user@host:22`。
界面中的主机和端口是独立字段。修改导入目标会建立应用保存的副本；移除只隐藏导入记录，
不会重写来源配置。

## 工具与 Skills

已安装、已配置、已验证是不同观察结果。CLI 与 VS Code 插件分别检测。
AI 路由开启后，检测到的兼容工具会自动准备，除非你已在本次会话中明确关闭对应工具。
兼容的远程插件不要求额外安装独立 CLI。

安装窗口提供由用户执行的命令、终端入口和重新检测，不会自动安装软件。Claude 优先使用原生安装方式。
若 `~/.local/bin` 不在 PATH 中，按窗口中的会话/PATH 指引处理。持久修改 Shell 启动文件是你自行选择的
手动操作，不是 RouteSpan 默认行为。通过 npm 安装的 Codex 也可能不在 PATH 中，应检查 npm 前缀和当前 Shell。

Claude npm 指引保留项目约定的 Node.js 18+ 与 npm 门槛，并单独标注已复核的官方推荐为 22+。
较低门槛不保证最新 npm 包可以在 Node.js 18 上运行。

展开概述中默认折叠的 Skills 管理器，可搜索并分别选择智能体的同步状态。
仅 CC Switch 托管的链接符合条件；原生 Skills 和 Codex `.system` 不会复制。
取消同步只移除应用管理的远端副本。

## 启动与验证

- **打开终端**：自动加载本次会话环境。
- **在 VS Code 中打开**：打开已确认的 SSH 目标，并尝试可恢复的远端网络设置。
  新服务器可能需要先由 Remote - SSH 初始化 Server；已有远程窗口按提示重新加载，并新建终端。
- **MobaXterm / 外部 SSH**：启动工具前，可能需要在已认证的远端 Shell 中执行复制的终端配置命令。

网络桥接就绪后会自动检查一次实际出口，但不能证明所有网站可访问。
内置模型验证只支持已安装的 Claude CLI，需主动执行且可能消耗 Token；Codex 应使用实际客户端验证。
高级页分别展示结果和最近事件。VS Code 的端口面板不是本次反向桥接状态的权威来源。

## 断开与恢复

传输中断会触发有次数/时限边界的同目标恢复；普通重试和成功保持静默。
认证、主机信任或配置发生变化时可能需要你处理。已经中断的应用请求不会自动重放。

断开先撤销中转，再清除会话 SSH 凭据，并尝试恢复应用管理的 VS Code 网络设置、清理会话导出。
已启用的工具配置会保留；关闭某个工具才能恢复其管理字段。恢复证据有变化时停止操作，
不覆盖用户修改。旧会话 Token 无法访问已断开的路由。
