# SSH connection manager — design

**Status:** implemented on `v0.2.0dev`; release acceptance remains pending. ProxyEnv automatically imports bounded OpenSSH, VS Code Remote SSH and MobaXterm sources, and can persist manually reviewed connections. Imported rows remain source-owned until edited. Editing one opens the same full form used to add a connection, saves an independent ProxyEnv connection, and hides only the imported display copy; the original SSH, VS Code or MobaXterm configuration is not modified or deleted. Existing structured target IDs bind source, file identity and alias/session. No private-key or credential contents are read.

## Import and manual entry

Import bounded OpenSSH `~/.ssh/config`, VS Code Remote SSH config and MobaXterm bookmark sources without scanning the disk. Do not parse Moba password, credential or master-password sections. Do not merge identically named targets from distinct sources.

The shared add/edit form contains display name (1–32 Unicode characters), host or `user@host`, SSH port (integer 1–65535), and authentication choice: **password authentication** (default for new connections), **Automatic OpenSSH**, or **specified identity file**. Automatic means native config, default keys, ssh-agent, password, keyboard-interactive and explicit first-use host-key confirmation—not “no authentication.” Password mode controls OpenSSH's authentication order but never stores the password. Resolve and validate host/port/identity file through the backend; store only a reviewed target definition, not secret material. Field errors share compact label-side tooltips instead of adding below-field rows; backend save failures remain in the open dialog. Existing longer imported/saved display names are not silently truncated; an edited record must satisfy the new name limit before saving.

Manual connections are stored separately from model/profile settings. Identity files are selected with the existing native file dialog, including extensionless id_ed25519/id_rsa files. Selection and saving reuse the same validator: an absolute path to a readable regular, non-symlink/non-reparse file of at most 1 MiB, with an OpenSSH or PEM private-key header. Device/extended paths, control characters and Windows filename metacharacters are rejected before filesystem access. A bounded first-line read checks only the format header, without buffering the key body; public keys and PuTTY .ppk files are rejected. This is not cryptographic or login validation: OpenSSH owns decoding, passphrase handling and server authentication. Only the normalized path is persisted, never key contents. Canceling the picker preserves the previous choice; selection errors remain inline. Removing a manual connection removes only this local definition.

## Connection and launch

Keep native OpenSSH as protocol owner and first try noninteractive authentication. Password, key passphrase, OTP and KBI responses are transient and must not be persisted. An unknown host requires explicit fingerprint approval; an existing `known_hosts` mismatch fails. Never disable strict host-key checking or forward Agent/X11 unexpectedly.

The setup UI groups targets by source in the fixed order OpenSSH, VS Code Remote, MobaXterm and ProxyEnv. It does not merge equal display names from different sources. Each card shows the connection name first, then the sanitized `host`, `user@host`, and port, plus source and detected authentication labels. OpenSSH effective configuration is used only to classify reliable identity-file, Agent, password or keyboard-interactive evidence; ambiguous cases remain “OpenSSH decides.” Adding, editing and copying all reuse the same form. Editing an imported target creates a full ProxyEnv-owned connection and leaves the original source untouched; editing an existing ProxyEnv connection preserves its ID. Capability selection and target choice share one setup surface, followed by one Connect action. ProxyEnv restores the last available selected target on the next visit. A successful interactive-authentication session continues directly into bridge construction.

For Moba, bookmark **import** is separate from **open**. ProxyEnv locates a running, installed, portable desktop or Start Menu MobaXterm entry. A selected compatible first-level bookmark opens with the documented `-bookmark` argument and its source INI passed through `-i`; another compatible SSH target opens MobaXterm itself so the user can continue there. The action appears only in the connected Overview after the bridge succeeds; target selection never launches MobaXterm. Nested bookmarks cannot be addressed safely through the bookmark interface and remain visible but Unsupported. Private authentication, complex jumps, macros, unsafe key conversion and opaque behavior also remain Unsupported. VS Code launches must match the selected effective SSH config; the managed terminal continues to use the existing PowerShell/OpenSSH flow.

## Verification

Automated coverage includes alias/source/path collisions, effective host/user/port and authentication classification, destination validation, device/extended/relative/missing identity-file rejection, first-level versus nested Moba bookmarks, separate safe launch arguments, OpenSSH hardening, first-use host-key parsing and password/KBI multi-round prompts. Real-device checks for a selected identity file and installed MobaXterm remain release-acceptance items. A successful SSH check does not imply a tunnel or remote tool is ready.
