# Remote Bridge UI/UX — Simple and Advanced

The connected page explains AI-only, proxy-only and combined use. Action availability follows the required capability: AI verification follows AI health; proxy testing/managed terminal follows General Proxy health; Skills follows the live SSH session. An unrelated unavailable route must not disable healthy actions.

Setup uses a fixed two-column workspace: choose an SSH connection on the left, then configure its capabilities on the right. The list shows at most five complete rows before scrolling internally; its scrollbar stays faint until hovered. Each row identifies its OpenSSH, VS Code Remote, MobaXterm or ProxyEnv source and authentication method. Outside clicks and Escape dismiss the action menu. Blank list space can clear the selection. Edit and add share one dialog; removing imported connections only hides them in ProxyEnv. Cancel and Establish bridge remain inside the current-connection panel, with the workspace border fully visible.

With no SSH connection selected, the existing instruction remains above decorative pixel mascots adapted from the user-supplied `proxyenv-pixel-mascots-v2` SVG/CSS assets and design board. Muted orange Claude and soft blue Codex have theme-aware palettes, with idle, coding, sleeping, music, coffee, reading, gardening and gaming actions. A finite action completes before a short fade switches to another random scene; every third scene pairs the characters for working, resting, gardening, gaming or music. Polling does not reroll the scene. The stage has a fixed size so switching cannot shift the page. These are illustrative mascots, not official brand logos or connection-result indicators. Reusable Vue/SVG sprites add no runtime dependency, network request or animation timer. Animation pauses when the remote page/document is hidden or the stage scrolls out of view, stops when selection removes it, and becomes static for reduced-motion users. It does not affect SSH selection, authentication or bridge operations.

The app shell fills the actual window rather than staying capped at the original 880px width. The header and any global warning reserve their own height; the page uses the remaining content area, not a viewport height minus a hard-coded header. Content has a 1360px maximum reading/workspace width on large displays. Above 760 CSS pixels setup keeps two columns; narrower windows stack the panels and reserve space for at least two complete SSH connections when present, including the list heading and row gap. Five complete SSH rows fit the normal desktop layout; short/narrow windows show fewer rows with internal scrolling instead of compressing their text. Current-connection content can scroll independently at constrained heights, while Cancel/Establish remain outside that scroller. Connected Overview/Advanced, local environment and settings scroll in the content area without moving the title bar. Authentication terminal content does not flex-shrink out of sight; constrained dialogs scroll internally.

Mascot scene completion uses a non-visual finite CSS clock on the HTML sprite wrapper, not SVG motion events. Its duration includes the complete action cycles and any partner delay. Reduced motion leaves the characters static but still rotates scenes at the normal pace without fades or movement; the app-wide shortened-animation rule must not turn it into rapid cycling. Hidden/offscreen stages pause both this clock and visual actions. A duet waits for both wrappers to complete, ignoring stale or duplicate completion events.

`scripts/test-remote-layout.mjs` is an optional Playwright geometry regression using the existing development review previews, not a real SSH target. Run a dev server, supply Playwright through the normal package lookup or `PROXYENV_LAYOUT_PLAYWRIGHT` (absolute package entry), and optionally supply `PROXYENV_LAYOUT_BROWSER` (installed Chromium executable). `PROXYENV_LAYOUT_URL` defaults to localhost:1420; `--screenshots` writes ignored previews under `.debug-tmp/remote-layout`. CSS viewport simulation does not substitute for real Windows 125%/150% display-scaling acceptance.

Bridge local network reuses the active proxy from Local environment. Local listener availability is separate from remote bridge connectivity. CC Switch AI routing requires a loopback listener owned by CC Switch and a bounded successful local `/health` response; an unidentified listener does not enable the switch. Detection confirms the shared local service, not individual Claude/Codex route toggles. Its detected URL appears beside the state. A short reminder asks users to enable the routes they need; no per-agent success badge or requirement to enable both routes is introduced. Discovery follows changed CC Switch ports, with no system proxy, redirects, credentials, AI requests or SSH probes. Loss of the route disables and clears the setup switch; its return makes the switch available without overriding the user's choice. Established tunnels keep their original endpoint and require reconnection after a route-port change. Both capability choices have equal height. The shared question-mark tooltip explains CC Switch → Settings → Routing → Local routing → Master routing switch → enable Claude/Codex routing. Setup omits the redundant subtitle, capability description and technical prerequisites. The backend still performs SSH validation and port allocation before forwarding.

CC Switch discovery starts when the app mounts, independently of SSH summary loading and before the remote page is opened. One application-owned cache and non-overlapping two-second polling provide the latest state and URL to setup, even while another page is visible. Entering setup consumes that cache in its first render, without a duplicate discovery. Refreshes retain the previous observation until the result arrives; unchanged observations do not replace the cached object, and a changed port is applied without an intermediate not-detected state. An unfinished first check is shown as checking, not missing. CC Switch AI routing defaults to enabled when detection confirms availability. A manual off choice is retained for the current page session. Temporary unavailability disables the effective switch without discarding that choice; recovery restores the preferred state instead of forcing routing on or leaving the default off. Background discovery never retargets an established bridge.

The shared Add/Edit SSH dialog keeps destination examples, authentication explanations, identity-path guidance and edit/copy explanations in the existing question-mark HelpTooltip instead of persistent paragraphs. Field-validation errors stay inline and associated with their input. The tooltip mounts inside its nearest open native dialog when present, keeping help visible and keyboard-accessible in the modal top layer; ordinary page tooltips still mount in the document body.

The compact identity authentication row reserves its single-line path area; Browse appears only when identity mode is selected, with a 30px action height inside a stable 36px row. Long paths are ellipsized with the full path available on hover. The native file picker accepts extensionless names; Rust validates path safety, readable regular-file metadata, size and a bounded OpenSSH/PEM header before returning only the normalized path. Cancel retains the previous selection. Saving revalidates the same file, and OpenSSH still owns actual key decoding, unlocking and server authentication.

All SSH form fields use the shared FieldValidation / HelpTooltip treatment: a red input border and a label-side error icon, with correction text available on hover or keyboard focus and linked to the field for screen readers. No below-field error rows expand the dialog. Invalid submit focuses the first invalid field. Names are limited to 32 Unicode characters in both frontend and backend, with a visible count. Save errors remain inside the open dialog, preserve input and clear on editing; a missing backend command explicitly requests a rebuild/restart rather than suggesting incorrect SSH or proxy settings.

Initial connection retains the setup layout through checking, SSH authentication and bridge construction. The original establish action stays visible, disabled and labeled Establishing bridge with a small inline spinner; no detached Processing status appears below the panels. The content-sized OpenSSH dialog is at most 440px wide with a 40px response field. Its submit action remains mounted during bridge construction and shows the same disabled loading treatment. Reduced-motion preferences keep textual feedback without rotation. Existing secret clearing and fixed-length password masking are preserved.

Authentication rejection and other errors appear in a reserved inline area beneath the response field, not as a floating notice. Error visibility does not move the field or resize the centered dialog; long messages scroll inside that area. The field references the error for accessibility. Dialog text is selectable, and Copy prompt reuses the shared modal-safe clipboard helper to copy the displayed OpenSSH prompt and localized error only—never the password, verification response or its mask. Copy success/failure feedback stays in the same button and does not change bridge state.

Selectable text includes the dialog title, status label, field label, fingerprint and diagnostic values, not only terminal output. Authentication focus watches individual prompt/status values rather than newly allocated polling snapshots, so an unchanged poll cannot refocus the password field and interrupt selection or Ctrl+C. New challenges retain the existing input-focus behavior without scrolling the dialog.

After the bridge is connected, the default next actions use the managed terminal, Open in VS Code, or—when MobaXterm is installed—Open in MobaXterm. MobaXterm is not launched from target selection. A selected first-level Moba bookmark opens that bookmark; another compatible SSH target opens the MobaXterm application so the user can continue with the same saved connection details. MobaXterm is a connected-target capability, not a General Proxy advanced action. A hint beside Open in VS Code explains that ProxyEnv temporarily isolates the remote account's VS Code Server from inherited proxy settings, keeps loopback AI routes direct, preserves local settings, and may require reloading an existing remote window. No third-party extension binary or user startup file is changed.

General Proxy has no username/password UI or fallback. Advanced shows its unauthenticated loopback-listener risk separately from the AI Route's session authentication, alongside the token-free terminal setup command and technical diagnostics. The AI Route's session header is never displayed or copied. Successful copying does not claim that a running extension host has received new environment variables.

## Simple (default)

The remote page mounts hidden at application startup and preloads its local SSH connection list. Local proxy and CC Switch observations initialize capability controls even if detection finishes after mounting. Opening the tab reveals the same page and list instance with `v-show`, rather than mounting an empty view and loading it on first navigation. Preloading does not connect SSH, start a bridge or enable AI tool access; an explicit capability choice is preserved across subsequent observations and page switches.

The connected page defaults to Overview, following the October connected-overview design. Its four groups are the bridge header, two equal capability cards, AI tools and Skills, and a bottom launch bar. The header shows one target and overall connection status, the SSH address/source/cleaned configuration path, and an independent server-direct observation. A failed server-direct check uses a yellow warning, not the bridge failure state. Overview/Advanced, Recheck and Disconnect remain together in the top toolbar.

Capability cards show the session's original local endpoint → remote loopback port, not the internal Relay's transient port. They do not substitute a newly selected local proxy into an existing bridge. Network proxy and AI routing retain separate health states and can be independently paused or resumed after connecting. Switches wait for backend confirmation and block repeated actions during setup/configuration. A paused relay closes its active connections and refuses new traffic while reserving the same forwarding port; the other relay and SSH transport remain intact. Recovery preserves paused gates. First-time activation adds only the requested forward, using existing SSH authentication and loopback verification rather than restarting the healthy lane. General Proxy pause removes its managed shell environment and updates/restores owned VS Code network settings. AI pause first restores the enabled tools through their existing hash-checked backup transactions; resume reapplies those tools with the current local profile. Multiple files remain separate transactions: a partial restore is explicitly reported with accurate tool states, never described as full success or overwritten on conflict. Existing processes need restarting after configuration changes. Codex and Claude Code access switches continue using the existing tool adapters.

The capability labels, addresses and client names share the SSH metadata's plain 11px typography. Local and remote labels share the first row and addresses share the second row, connected by a plain muted arrow aligned with the addresses. Client and protocol details sit separately below the local address. Both cards use the same column proportions and row spacing. Long content wraps within its column rather than needing horizontal scrolling or expanding the page. The header's Server direct network observation has a small globe icon and concise Available/Unavailable badges; unknown, checking and not-yet-checked remain distinct. An unavailable direct connection uses a warning treatment and does not imply bridge failure.

AI tools appear side by side in compact rows, with bundled OpenAI/Claude identifying marks and one configuration state per tool. While the existing post-connect Codex/Claude runtime state is pending or preparing, that tool displays the shared Checking spinner and blocks both enabling and disabling in Overview; its real checked state is preserved. Advanced mirrors the checking state in read-only tool summaries. Each Overview tool unlocks independently when its check finishes, including warning outcomes, and reconnect applies the same lock. No additional detection requests are introduced. Configuration does not imply successful AI requests; Codex synchronization is not inferred from Claude's profile state. Skills default to a collapsed summary showing the number of unique local linked names and the synchronized/enabled agent-projection count. Manage expands the manager in Overview, never navigates to Advanced. Case-insensitive name search filters merged rows; each agent has its own status and Sync/Stop syncing action, wired to the same existing enable/disable commands and polling loop. Missing local links are disabled. Actions wait for backend confirmation, block duplicates and retain the prior state on failure. Stopping sync removes only the managed remote projection, not local Skills or unmanaged remote files. A brief explanation and agent-restart guidance remain inside the expanded manager; its list has bounded, keyboard-accessible scrolling and a subtle hover scrollbar. Search and expansion reset for a different SSH target, not for routine refreshes.

Skills management uses a gear-only button with an accessible Manage/Collapse label and expanded state. It reveals a compact searchable table: one Skill per row, with fixed Codex and Claude Code columns containing the synchronization status and shared-style switch. Agent names and icons appear only in the sticky column header, not repeated for each Skill; narrow windows keep the same three-column structure without stacking ordinary rows. The creation/removal safety explanation lives in the pinned question-mark help next to Remote Skills; restart guidance remains in the expanded manager. Pending actions show Checking, lock controls and preserve the last confirmed switch state. Disconnect uses danger-colored text and a matching unlink icon, with the existing confirmation dialog unchanged.

The Overview content scroller and the nested Skills list keep a narrow scroll lane allocated with `overflow-y: scroll`, alongside a stable scrollbar gutter. Opening/closing Manage or filtering across a scrolling threshold must not change the horizontal position or width of the window header, workspace, cards, table columns or launch bar. Terminal, VS Code and MobaXterm remain visible in that order in a separate bottom launch bar, with bundled official application icons. ## Silent transport recovery

After an established bridge loses SSH transport, the backend attempts recovery without reopening the setup flow. It reuses the selected target, ports, live relays and bridge-scoped SSH session credentials. A small in-page reconnecting status is sufficient: temporary outages, retries and successful recovery produce no popup or sound. Recovery starts by rebuilding the retained tunnel directly and uses a bounded 1, 2, 4, 8, 15 and 30 second backoff instead of waiting several minutes behind a separate SSH probe. Interrupted application requests are not replayed; the user may need to retry the affected message after recovery.

Authentication failure, a changed host/configuration or a changed active proxy pauses recovery. The page keeps the reason and retry action beside the connection status; it does not create a second lower-right in-app card. Manual retry resumes the retained target, ports, relays and session instead of rebuilding setup input. No password prompt opens automatically. Native reconnect notifications and their settings remain dormant in `v0.2.0dev`; recovery is silent unless inline user action is required. SSH login authentication remains independent from the removed General Proxy username/password feature. Manual disconnect, target replacement and app exit cancel pending recovery; recovery must never recreate a user-disconnected bridge.

## Advanced

Advanced is the connected bridge's Operate surface for diagnosis and safe manual repair. It extends the established warm Overview treatment and the authoritative product/design system. At desktop widths it pairs Environment configuration with Link status, then Security and risk with Manual tools, then Recent events with Diagnostic report. At 760 CSS pixels and below these six sections stack in the same reading order. Warm semantic surfaces, fine borders, restrained icons and wrapping status rows preserve the existing light/dark hierarchy. Manual-action grids also stack at 420 CSS pixels and below.

Environment configuration separates the managed terminal's session-environment readiness, external terminals' manual-load requirement, VS Code configuration readiness and runtime-port match. Codex, Claude Code and Skills detection summaries and management remain in Overview rather than being duplicated here. Each desktop left/right card pair stretches to equal height. Link status presents tunnel/egress, tunnel/model request and SSH authentication/recovery as three left/right pairs with a subtle divider; a card narrower than 270px stacks the pairs to keep long states readable. An established General Proxy/AI tunnel remains distinct from evidence of an actual proxy egress or supported model request. Configured, ready and established states must never imply successful model traffic. Unknown, checking, unsupported, failed and verified observations remain distinct. SSH transport displays the reported authentication method and recovery state rather than inferring them from another lane's status.

The terminal command preview uses the existing session-environment command API only while Advanced is visible and the General Proxy's session environment is already ready. This prevents inspection from starting optional environment setup while it is pending. The preview shows loading or unavailable feedback and rejects stale responses after its context changes; it never synthesizes an export block. Explicit Copy setup command uses the existing command/clipboard handler. Viewing Advanced does not run model requests, reconnect, enable routes or silently configure tools.

Run diagnostics explicitly invokes the backend runtime coordinator through `remote_bridge_run_diagnostics`. It reuses the existing server-direct check, General Proxy SSH egress probe and supported AI-tool verifier, rejects duplicate runs and binds the entire run to one connection generation. Unconfigured, unsupported, pending or preparing AI tools are skipped. A failed server-direct or proxy probe does not suppress the independent AI verification; diagnostics do not reconnect or toggle either lane. Claude Code uses its existing supported model-request verifier; Codex verification remains unsupported and must never appear verified merely because its configuration is ready. `remote_bridge_diagnostics_snapshot` reads cached observations plus SSH/VS Code state and never opens a socket or launches SSH.

Server-direct, General Proxy egress and AI-route verification use backend session-cached `DiagnosticObservation` snapshots with `state`, `checkedAt`, typed error category in `errorCode`, and `durationMs`; the snapshot also retains the server's reachable/unreachable/unknown result. States are not tested, testing, passed and failed. Returning to Advanced reads the existing proof without another probe. The private observation revision is not serialized. Probe results are accepted only for the current connection generation, observation ticket and applicable target/fingerprint or lane context; late results cannot mark a changed or disconnected bridge verified. SSH probe I/O runs outside the bridge store lock so snapshots and Disconnect remain available. Transport and capability changes invalidate affected proof independently, and supported-tool apply, restore or verification reset invalidates AI proof. These observations are kept in memory for the bridge session, not persisted as diagnostic snapshots or a guarantee for later requests.

Security and risk reads backend `SecuritySnapshot` policy facts: `generalProxyAuth: none`, `aiRouteAuth: session`, `remoteBindScope: loopback` and `shellScope: sessionOnly`. The same allowlisted snapshot appears in the existing report. Remote loopback binding remains separate from authentication: General Proxy's lack of proxy authentication is an amber risk, while the AI Route's session authentication is a separate state, with no token displayed or copied. These are policy facts, not an additional security probe. The SSH credential-cache row uses the actual backend `passwordStored` value, and Clear session credential is available only when a credential is stored. Clearing updates both backend authentication snapshots to `passwordStored: false` and records an actual credential-clear event. This action concerns the SSH session cache, not proxy credentials.

Manual tools reuse the existing setup-command copy and manual-terminal actions. Open SSH configuration and Reveal configuration appear only for OpenSSH or VS Code sources; VS Code settings appears only for a VS Code source. Manual and MobaXterm targets receive an explanatory unavailable state rather than configuration-file actions. These source actions remain absent from setup and Overview. Protected tool dialogs continue to own tool versions, extension runtime, profile/catalog state and restore diagnostics.

Recent events reads actual backend outcomes from a bounded memory store of at most 100 entries, newest first. The `remote_bridge_events` command clamps the requested limit to that capacity; Advanced requests the latest 50 through `remoteBackend.events()`. Events contain only timestamp, level, component, action, outcome, typed error category and optional duration, with no free-form payload. Recorded actions include connection/disconnection and transport recovery, actual post-connect environment/VS Code/tool configuration outcomes, manual Skills changes, server-direct checks, egress/model probes and credential clearing. Starting a new bridge clears the previous in-memory history; application shutdown clears the memory store. The separate rolling log preserves only the same allowlisted event records.

The Recent events list is keyboard-scrollable with a bounded height and localized action/outcome/category labels. Advanced polls this local snapshot and local log-storage availability every two seconds only while the Advanced view and Remote Bridge page are visible, discards responses from a previous visibility/target context, and stops polling when hidden or unmounted. The watcher compares visibility and target ID as separate primitive sources: fresh but unchanged summary objects do not restart polling or clear the list/log availability. Hiding and reopening the same target retains the cached display; changing targets clears it. A temporarily unavailable event snapshot retains the last safe list; an initial request and a successfully loaded empty list have separate feedback. Viewing Advanced and reading its events do not initiate SSH or model tests. A synthetic delayed-response regression first reproduced event-list removal, then verified zero list removals and zero transient log-button disables across multiple unchanged polling snapshots after the fix.

Diagnostic report opens the existing global report dialog. Its existing safe DTO adds reconnect state, SSH authentication method, runtime-port match, post-connect and per-component preparation states, typed error category, allowlisted phase timings, cached server-direct/egress/AI observations and the security policy snapshot. Report generation reads the Remote Bridge cache without SSH or socket probes. The projection excludes target identity, configuration paths, tokens, request content and URLs; timing phase/outcome values are allowlisted and arbitrary error text is reduced to a category. The formatter localizes the added states in Chinese, English, Japanese and Korean within the existing report UI.

Connection timings opens a native, internally scrolling dialog containing the existing `summary.timings` phase, duration and outcome rows, or an explicit empty state. Its content has 20px inset padding and the close-action form adds no second inset. Phase 2 P0/P1 supplies cached proof, real bounded events, the runtime coordinator, rolling logs, security policy facts and the report extension.

Open log folder is enabled only when the local logging worker reports healthy storage; its four-language help explains redaction and rotation, or an unavailable-storage recovery step. A logging failure disables this action without blocking the bridge. Logs live in `remote-bridge` beneath Tauri's application log directory and contain typed JSONL event records with INFO/WARN/ERROR levels. Debug builds may also record the fixed DEBUG phase `diagnostics.run`. The logger does not subscribe to global tracing or store raw model content, tokens, paths or requests. A bounded 256-entry asynchronous queue uses nonblocking sends; a full queue drops a log record rather than delaying SSH or relay traffic. Each of the three fixed files is limited to 2 MiB. Directory ancestors and file operations use the shared local-file safety boundary, including symlink/junction checks. Shutdown makes a best-effort queue drain with a wait bounded to two seconds; complete log delivery is not guaranteed.

Overview/Advanced uses in-place visibility changes, so toggling preserves Overview's tool controls, Skills state and operation feedback. The segmented control exposes pressed state and keyboard focus, follows reduced-motion behavior, and ships equivalent Chinese, English, Japanese and Korean copy. Advanced help uses the shared pinnable tooltip for selectable, viewport-bounded explanations. ### 概述与高级共用连接外壳

两种视图共用同一个固定高度外框、标题操作栏、SSH 摘要和服务器直连状态；连接摘要位于滚动内容之外。只有下方内容区切换，统一保留滚动条槽位，不重新创建顶部。切换后内容从顶部开始，概述的 Skills 展开状态仍保留。按最新界面要求移除检测时间显示，保留重新检测及诊断功能。合成 IPC 浏览器回归比较宽屏、常规和窄屏浅色/深色下的外框及顶部矩形，覆盖滚动后双向切换，防止布局位移；不代替真实 SSH 验收。

### 首次 SSH 连接与 VS Code 入口

- 列表、当前连接和连接后概述复用同一地址格式：默认 SSH 端口 `22` 不加地址后缀，非默认端口仍显示；编辑表单和实际 SSH 连接仍保留端口值。
- 首次连接未信任的服务器时，严格检查失败后进入现有 OpenSSH 交互窗口，由用户确认主机指纹，再完成密码或密钥认证。已存主机密钥发生变化时仍阻止连接，不自动接受、不删除 `known_hosts`。
- ProxyEnv 手动连接不再一律禁用 VS Code：普通直连目标通过 Remote - SSH 的结构化 authority 传递主机、用户名、端口；已有同端点、同身份文件且 VS Code 可用的 SSH 条目可复用其别名。不改写用户 SSH 配置或 VS Code 设置。
- 非默认身份文件无法匹配既有条目、或 VS Code 使用不同 SSH 配置时，保留目标一致性限制，不静默忽略密钥或切换配置。新服务器尚未安装 VS Code Server 的提示不阻止启动 Remote - SSH，由 VS Code 完成首次安装后再重新打开以配置网络。

### 验证请求与配置同步

- 高级页的 Claude 模型请求使用隔离临时配置，保留当前远端的模型选择和已同步模型映射，注入本次会话鉴权。排除真实凭据、Hooks、MCP 和其它非模型配置；清除继承的代理和供应商环境，明确绕过 loopback 代理，不改写用户配置。验证仍有超时上限，真实对话正常不代表独立验证必定成功。
- “用户代理端口”只对照本机 VS Code 默认用户设置与远端桥接端口，不检测扩展运行进程。未知显示“无法确认”，不匹配作为提醒而非插件不可用的证明；Profile、远端/工作区设置可能覆盖默认设置。
- Codex 与 Claude 共用桥接期间的配置同步流程：元数据轮询、防抖、校验、哈希比较、原子写入。读取 Claude 时核对前后文件元数据，既有文件暂时消失时保留最后可用配置；写入前再次检查本机变化和连接上下文。远端 apply 完成实际回读后返回端口和配置哈希，避免重复第三次 SSH 往返。同步不会终止运行中的 Agent；配置更新后的重启提示不会被无关保存清除。
- SSH 认证行仅在当前连接且后端确认认证成功时使用绿色对号，其余状态保持中性。
- 已确认的“仅当前会话”和“未缓存”使用绿色对号。会话安全操作仅在后端确实缓存了本次桥接密码时显示，不提供无效清除按钮；不移除自动重连的会话级加密缓存。第二行安全与边界、手动工具保持等高。
- 显式诊断并行运行服务器直连、代理出口和已开启且支持验证的 AI 工具检查；各项仍沿用原有上下文校验及独立结果，某一项失败不阻塞其它检查。模型请求行只显示状态，失败原因以“验证失败 · 错误类别”放在最近事件中，不显示原始错误或模型响应。Codex 当前不支持安全独立请求验证，保持明确的“不支持验证”，不伪造成功。

### 诊断帮助与日志清理

- 报告预览和日志目录的说明统一放在“诊断”标题旁的可固定问号中，不占正文空间。
- “打开日志目录”之后提供“清除日志”，必须确认后执行。通过同一个日志写入队列，仅清空固定的 `bridge-0.jsonl`、`bridge-1.jsonl`、`bridge-2.jsonl` 内容，不删除目录或其它文件，不影响配置、凭据及恢复文件。先校验所有目标及祖先目录，遇到不安全路径或写入失败停止；后续事件继续记录。此操作不清除内存中的最近事件。
- 外部终端状态使用“需手动执行”，终端配置命令保持左对齐、单行省略；右侧固定尺寸的复制图标复用概述的复制状态和处理函数，只有复制成功才显示绿色对号。
- 概述和高级页的终端复制共用独立的 pending/success 状态，仅锁定复制入口，不触发页面级 busy、整页透明度变化或额外反馈行。绿色对号在两秒后恢复；切换桥接目标、断开连接、离开页面及卸载均清理反馈，旧会话的异步结果不能激活新会话的成功状态。
